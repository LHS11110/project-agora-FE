# 캔버스 GitHub 버전 관리

**캔버스 상단 → 변경 이력 → 저장소 연결**에서 저장소 소유자, 이름, 브랜치와 JSON 경로를 입력한다. 기본 경로는 `canvases/<canvasId>.canvas.json`이며 브랜치를 비우면 기본 브랜치를 사용한다. 소유자/저장소 이름 외에 GitHub 저장소 URL, `owner/repo`, HTTPS/SSH clone URL도 입력할 수 있다. 빈 저장소도 연결할 수 있으며 첫 캔버스 커밋이 기본 브랜치와 첫 파일을 생성한다. 빈 저장소에서 브랜치 입력은 비워두거나 저장소의 기본 브랜치를 지정한다. 저장소 자체 생성은 수행하지 않는다. 첫 커밋 후에는 새 브랜치와 별도 캔버스를 만들 수 있다.

대상 저장소에 한정한 Fine-grained personal access token에 **Contents: Read and write** 권한을 부여해 입력한다. 브라우저가 `https://api.github.com`에 직접 요청하며 FreLog 서버는 GitHub 토큰을 받지 않는다. 검증된 토큰은 현재 HTTPS 출처의 IndexedDB에 AES-GCM으로 암호화해 24시간 보관한다. 키는 추출 불가 CryptoKey로 저장한다. 닫았다 다시 열거나 같은 저장소의 다른 브랜치로 이동해도 만료 전 자동 입력된다. 읽기나 재접속으로 만료를 연장하지 않는다. 사용자가 토큰 삭제 버튼을 누르거나 저장 기한이 지나면 다시 입력해야 한다. localStorage에는 소유자·저장소·브랜치·경로만 캔버스별로 보관한다. 토큰 원문은 localStorage/sessionStorage에 저장하지 않는다. Google/Naver/Kakao 로그인 토큰은 GitHub 인증에 사용하지 않는다.

1. **저장소 연결 · 새로고침**으로 대상 브랜치와 파일 상태를 확인한다.
2. **현재 캔버스 검토**로 현재 클라이언트의 캔버스 스냅샷을 준비한다. 편집기의 미적용 JSON을 전송하는 기능이 아니다.
3. 준비된 코드·대상·메시지를 확인하고 **검토한 캔버스를 GitHub에 커밋**한다. 다른 화면/사용자가 변경한 뒤에는 다시 검토해야 한다.
4. **저장 이력**에서 버전을 선택해 편집기로 불러온다. 기존의 **변경 검토 → 검토한 변경 적용**으로 복원한다. 이때 일반 객체 편집과 동일하게 권한·잠금·저장·브로드캐스팅 경로를 따른다.

GitHub에 기록하는 것은 UTF-8 JSON 스냅샷이다. `mode: replace`로 저장해 복원 시 해당 버전에 없는 객체의 삭제도 검토할 수 있다. 대상은 현재 클라이언트가 볼 수 있는 객체이며, 서버 설정·채팅·댓글·미확인 멘션·가상머신 파일·이미지/PDF 바이너리 자체는 포함하지 않는다. 이미지/PDF는 기존 리소스 주소를 참조하므로 리소스와 캔버스 접근 권한이 유지되어야 한다. 공개 저장소에 커밋하면 JSON 내용도 공개된다.

현재 클라이언트 상태를 캡처하므로 서버 저장 승인 전의 로컬 변경이 포함될 수 있다. FreLog 서버의 저장 백업이나 모든 사용자의 전체 상태 백업과 동일하지 않다. 브라우저가 볼 수 없는 그룹의 객체를 내보내거나 복원할 수 없다.

## 충돌과 오류

기존 파일의 blob SHA를 [Contents API](https://docs.github.com/en/rest/repos/contents)에 전달해 수정한다. 다른 사용자가 같은 파일을 수정하면 409/422를 안내하고 자동 덮어쓰기나 재시도를 하지 않는다. 다시 연결한 뒤 최신 파일을 확인하고 재검토한다. 내용이 연결 시점의 파일과 같으면 새 커밋을 만들지 않는다. 커밋 성공 후 이력 갱신만 실패한 경우에는 성공 상태를 유지한다.

파일 경로와 참조는 인코딩하며 요청 대상은 GitHub API로 고정한다. 요청 인증값은 Authorization 헤더에만 넣고 URL/로그에는 넣지 않는다. 브라우저에는 아래 설명처럼 24시간 암호화 보관한다. 리다이렉트는 따르지 않는다. 파일은 8MiB 이하를 지원한다. 이력은 [파일 경로와 브랜치로 제한한 Commits API](https://docs.github.com/en/rest/commits/commits)를 사용해 20개씩 가져온다. 보호 브랜치나 토큰 정책에 의해 직접 커밋이 거부될 수 있으며 PR 생성은 별도 권한으로 제공하며 강제 푸시는 수행하지 않는다. 요청 시간 초과 시에는 GitHub에서 실제 커밋 여부를 확인한 뒤 재시도해야 한다.

## 검증

`tests/githubCanvas.test.js`에서 UTF-8/base64, 크기·대상 검증, 생성·SHA 업데이트, 파일별 이력, 이력 파일 로딩, 오류 시 재시도/인증값 노출 방지를 검사한다.

`tests/integration/canvas-github.mjs`는 실제 캔버스 UI 두 개와 격리된 API/브로커/GitHub 대역으로 스냅샷 커밋, 변경 없는 커밋 생략, 과거 버전의 검토 후 복원과 다른 화면 전달, SHA 충돌 차단, 패널 재개방 시 유효 토큰 자동 입력, 모바일 레이아웃을 확인한다. 이 테스트는 실제 사용자 저장소에 커밋하지 않는다.

## 브랜치별 실제 캔버스와 병합

캔버스 관리자가 **브랜치 연결 · 목록 갱신**을 누르면 현재 방을 현재 브랜치에 연결한다. 브랜치를 선택하고 **별도 브랜치 캔버스로 이동**하면 브랜치별로 재사용되는 별도 캔버스 ID로 이동한다. 아직 방이 없으면 원본 공개 여부·비밀번호를 상속한 새 캔버스를 만들고 해당 GitHub 브랜치의 JSON을 저장한 뒤 이동한다. **새 브랜치와 캔버스 만들기**는 현재 브랜치의 GitHub HEAD에서 새 Git ref와 별도 방을 만든다. 새 방은 GitHub에 커밋된 내용을 기준으로 시작하며 이전 방의 미커밋 작업은 이전 방에 남는다.

서버는 캔버스 리소스 볼륨에 프로젝트 대상과 `branch → canvasId, initialized` 연결을 보관한다. 클라이언트의 localStorage가 연결의 원장이 아니다. 자식 방에는 루트 ID 포인터만 저장하고 실제 연결은 루트에 둔다. 파일 잠금과 원자적 파일 교체로 동시 생성 및 재시작을 처리한다. 같은 브랜치를 다시 열면 기존 방을 반환하며 최대 128개 방을 연결한다. 초기화 중 중단된 방은 다음 전환 시 초기화를 다시 시도한다. 관리자만 프로젝트 연결과 저장소 변경을 수행한다. 그룹에 위임된 브랜치 생성·이동 권한과 기존 캔버스 접근 권한으로 브랜치 방을 관리한다.

분리된 방은 분기한 현재 캔버스의 소유자·초대 사용자·그룹·그룹 비트·권한·초기 그룹을 생성 시점에 복사하고 원본 공개 여부와 비밀번호 해시·비밀번호 버전을 상속한다. 이후 초대/권한 변경은 방별로 관리한다. 채팅·통화·VM 실행 환경은 캔버스 ID가 다르므로 별개다. 이미지/PDF의 원본 주소는 여전히 원래 방을 참조하므로 원래 방의 접근 권한도 필요하다. 루트 방을 삭제하면 프로젝트 연결을 관리할 수 없으므로 브랜치 방을 정리하기 전에는 루트를 유지해야 한다.

대상 방에서 **선택 브랜치를 현재 브랜치에 병합**하면 다음 순서로 진행한다.

1. 현재 로컬 상태와 대상/소스 방의 서버 저장 상태가 GitHub 파일과 일치하는지 검사한다. 미커밋 변경이 있으면 먼저 커밋하도록 안내한다.
2. 브라우저가 GitHub [Merge API](https://docs.github.com/en/rest/branches/branches#merge-a-branch)를 호출한다. 충돌이나 브랜치 보호는 우회하지 않는다.
3. 병합된 파일을 다시 가져와 대상 방에 인증된 짧은 WebSocket 연결로 반영한다. 기존 `ServerCanvasSession`의 순서·요청 ID·수신 확인 프로토콜을 재사용하고 브로커의 저장 후 브로드캐스팅을 기다린다. 대상 방에 다른 사용자가 접속해 있다면 해당 변경을 받는다. 소스 방은 변경하지 않는다.
4. 저장 확인 후 완료를 표시한다. GitHub 병합은 성공했지만 캔버스 반영이 실패하면 그 사실을 안내한다. **브랜치 최신 커밋 복구**로 다시 적용할 수 있다.

GitHub 웹사이트 등 외부에서 병합한 경우에도 **브랜치 최신 커밋 복구**로 적용할 수 있다. 외부 병합을 상시 감시하는 웹훅/백그라운드 동기화는 포함하지 않는다. GitHub 토큰은 브라우저에서만 사용하며 FreLog 서버에는 전달하지 않는다.

변경 이력 탭의 **이 커밋으로 캔버스 복구**는 편집기에 불러오기만 하는 대신 해당 커밋을 실제 캔버스에 저장한다. 없는 객체와 생략된 속성도 제거한다. 텍스트는 기존 CRDT 이력을 기반으로 변경을 만들고 색상 표기를 복원한다. 잠긴 객체와 권한 제한은 우회하지 않으며, 같은 객체 ID의 종류 변경은 거부한다. 여러 저장 배치 중 오류가 발생하면 일부 변경이 저장되었을 수 있으므로 대상 상태를 확인한 뒤 재시도해야 한다. 복구는 GitHub 이력을 강제로 되돌리지 않으며, 복구 결과를 다시 커밋하면 새 버전으로 남는다.

추가 검증: `tests/branchRestore.test.js`, GitHub branch/ref/merge 단위 테스트, 백엔드 `CanvasGithubServiceTest`와 `CanvasServiceTest`, `tests/integration/canvas-branches.mjs`. 브라우저 테스트는 API·GitHub·브로커 대역으로 방별 데이터 격리, 초기화 후 전환, 병합 후 저장과 전달, 과거 커밋의 삭제 포함 복원, 다른 브랜치 보존을 확인한다.

### 연결 안내와 빈 저장소

연결 버튼은 토큰/입력값이 없더라도 눌러 구체적인 안내를 확인할 수 있다. 진행·연결됨·오류를 버튼 바로 아래에 표시하고 오류/완료 메시지로 스크롤한다. 소유자는 캔버스의 소유자 표시명이 아니라 GitHub 계정 또는 조직명이다. URL을 입력하면 소유자와 저장소 이름을 자동으로 분리한다.

브랜치 조회가 404/409일 때 브랜치 목록까지 조회해 빈 저장소를 구분한다. 기존 브랜치가 있는 저장소의 오타나 접근 권한 오류를 빈 저장소로 취급하지 않는다. GitHub 연결 확인에서는 GET만 수행하고 관리자의 연결 설정은 FreLog 서버에 저장한다. 최초 명시적 커밋에 한해 Contents PUT의 기본 브랜치 생성 동작을 사용한다. [GitHub 공식 빈 저장소 초기화 안내](https://docs.github.com/en/rest/guides/using-the-rest-api-to-interact-with-your-git-database)를 따른다.

## 전용 관리 화면

상단 **변경 이력**은 캔버스 코드 편집기와 분리된 대화상자다. **변경 이력 / 저장소 연결 / 브랜치 관리** 탭에서 각각 저장·복구, 인증/대상 설정, 분리된 방과 병합을 다룬다. 저장소 연결 성공 후 변경 이력 탭으로 이동하며, 브랜치/파일 경로는 고급 연결 설정에서 바꾼다. 탭 전환 중 연결과 토큰을 유지하고, 창을 다시 열면 24시간 보관 기한 안의 토큰을 자동 입력한다.

커밋 행의 **코드로 검토**는 해당 버전을 별도의 캔버스 코드 창으로 연다. 코드 창에는 GitHub 연결 폼이 없다. 대화상자가 열려 있는 동안 글로벌 뮤직 조작 UI/자막은 숨기되 iframe은 마운트 상태로 유지한다. 창을 닫으면 조작 UI가 다시 표시된다.

`canvas-github.mjs`에서 두 화면의 저장·복구 외에 독립된 관리창/탭, 코드 검토 창 전환, 데스크톱/모바일 진입, 뮤직 버튼을 적용/복구 버튼 위치에 배치해도 가리지 않음, iframe 노드 유지도 검증한다. 실제 외부 영상의 오디오 재생은 이 UI 테스트에서 측정하지 않는다.

## 그룹별 작업 권한과 저장소 관리

프로젝트 루트 관리자가 저장소 연결/변경 및 그룹별 권한을 설정한다. 일반 그룹은 기본 거부이며 `commit`, `push`, `pr`, `create_branch`, `switch_branch`를 각각 허용한다. 관리자는 복구·직접 병합까지 사용할 수 있고 일반 사용자는 위임된 작업만 사용할 수 있다. 브랜치 생성은 캔버스 쓰기 권한도 필요하며, 이동은 대상 방의 기존 읽기/입장 권한을 함께 확인한다. 생성 권한이 없는 사용자는 이미 생성된 브랜치 방 목록에서 이동한다. 새 브랜치 방에는 생성 시점의 원본 공개 여부·비밀번호 해시·비밀번호 버전을 복사하고 이후 설정은 방별로 관리한다. 유효한 원본 입장 인증과 동일한 비밀번호 해시를 확인한 경우 대상 방 전용 입장 인증을 발급한다. 이 인증은 원본 인증의 남은 만료 시간을 넘지 않는다.

저장소 연결은 관리자의 명시적인 연결 요청에서 서버에 기록된다. 일반 사용자는 이 저장소를 읽어오는 버튼만 사용하며 소유자·저장소·경로·현재 브랜치 설정은 바꾸지 못한다. 관리자 저장소 변경은 연결된 프로젝트의 모든 브랜치 방에 적용된다. 모든 보호된 앱 작업 전에 `/github/authorize`가 현재 그룹과 대상 저장소·브랜치를 검사한다. 권한을 회수하면 기존에 버튼이 활성화되어 있더라도 다음 요청은 거부된다.

**로컬 커밋 저장**은 브라우저 IndexedDB에 변경 불가 스냅샷을 저장하고 **푸시**는 이를 GitHub에 전송한다. 로컬 커밋과 푸시는 별도 권한이다. 기존 한 번에 커밋/전송하는 버튼은 두 권한을 모두 요구한다. 로컬 커밋은 사용자·출처·캔버스별로 구분하며 생성한 기록의 삭제도 가능하다. 서버 파일 SHA가 바뀌면 GitHub가 푸시를 거부하므로 최신 상태를 확인하고 새 커밋을 만들어야 한다. **PR 생성**은 별도 권한이며 대상 브랜치와 제목을 지정한다. 토큰에 GitHub의 Pull requests 쓰기 권한도 있어야 한다.

일반 사용자가 보이는 객체만 내보낼 때는 기존 GitHub 스냅샷의 보이지 않는 그룹 객체를 유지하여 의도하지 않은 삭제를 줄인다. GitHub 파일 자체의 가시성은 GitHub 저장소 권한을 따른다. FreLog 객체 그룹은 저장소 안의 JSON을 암호화하거나 GitHub의 읽기 권한을 분할하는 기능이 아니다.

## 토큰 보관 경계

IndexedDB는 [동일 출처 정책](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Basic_Terminology)을 따른다. `https://frelog.p-e.kr`에서 저장한 키/암호문은 다른 프로토콜·도메인·포트의 저장소와 분리된다. 계정/저장소를 AES-GCM 추가 인증 데이터에 포함하고 만료 시각을 검사한다. 토큰과 만료 기한은 읽어서 자동 연장하지 않는다. 닫힌 브라우저에서는 타이머가 실행되지 않으므로 물리적 삭제는 다음 읽기 시 수행될 수 있지만 만료된 토큰은 자동 입력하지 않는다.

브라우저의 같은 출처 스크립트는 키를 사용해 복호화할 수 있으므로 XSS를 방어하는 비밀 저장소는 아니다. PAT 자체에 URL 사용 제한을 부여하는 기능도 아니다. PAT를 가진 사용자는 외부에서 GitHub API를 호출할 수 있어 FreLog의 앱 권한으로 그 외부 사용까지 강제 차단할 수 없다. GitHub의 최소 저장소 권한, 1일 만료 및 브랜치 보호 규칙을 함께 설정해야 한다. 이를 완전히 중개하려면 클라이언트 PAT 대신 별도의 GitHub App/서버 중개 구조가 필요하다.

추가 검증은 실제 브라우저 IndexedDB의 비평문 암호문·추출 불가 키·출처 키·24시간 기한·만료 후 미입력, 일반 그룹의 로컬 커밋과 푸시 분리, 서버 회수 후 GitHub 쓰기 차단, PR 생성과 관리자 전용 설정을 검사한다. 백엔드 테스트는 기본 거부·그룹 부여/회수·잘못된 저장소 대상 거부·관리자 변경·비밀번호 상속을 검사한다. GitHub 외부 쓰기는 대역으로 격리한다.

## Git 커밋 그래프

변경 이력은 실제 커밋 부모 SHA를 연결하는 Git 그래프다. 최신 기록을 위에 배치하며, 작성 시각이 어긋나도 자식 커밋이 부모보다 먼저 보이도록 위상 정렬한다. 색상별 레인으로 분기와 병합을 표시하고 브랜치 이름과 현재 `HEAD`를 붙인다. 아직 불러오지 않은 부모로 향하는 선은 점선이며 **이전 커밋 더 보기**로 이어서 불러온다.

변경 이력은 현재 연결된 브랜치만 조회한다. 현재 브랜치 정보 한 번과 `commits?sha=<현재 브랜치>` 한 번을 요청하며, 다른 브랜치 목록이나 그 브랜치의 커밋을 합치지 않는다. 페이지마다 최대 20개를 가져오며 파일 범위 필터와 더 보기도 같은 브랜치를 사용한다. 현재 브랜치에 이미 병합되어 도달 가능한 커밋은 포함하고, 다른 브랜치에만 존재하는 독립 커밋은 제외한다. 해당 캔버스 파일이 없는 커밋에서는 복구/코드 검토가 불가능하다는 오류를 표시한다. 복구 권한과 기존 서버 저장 확인 절차는 그대로 적용한다. 그래프 새로고침은 GitHub 읽기 요청만 수행한다.

## 연결 유지

버전 관리 창은 최초로 연 뒤 같은 캔버스 작업 화면 안에서 상태를 유지한다. 창을 닫아도 저장소 연결, 커밋 그래프, 브랜치 목록 및 선택은 유지되며, 다시 열 때 캔버스 서버에서 현재 권한을 재조회한다. 닫힌 창은 숨겨지고 모달/포커스/뮤직 UI를 차단하지 않는다. 연결 성공 시점부터 30분이 지나면 연결과 검토 스냅샷 및 그래프를 해제하고 재연결을 요청한다. 창을 여닫거나 이력을 조회해도 유지 시간이 연장되지 않는다. 새로고침·캔버스 이동·페이지 이탈 시 메모리 상태는 사라진다. GitHub 토큰의 별도 24시간 보관 및 작업별 서버 권한 재검사는 유지한다.

## 종류별 파일과 권한 파일

새 저장은 기존 경로를 인덱스로 사용하는 v2 분할 형식이다. 예를 들어 `canvases/2102.canvas.json`을 연결하면 다음 파일을 사용한다.

```text
canvases/2102.canvas.json                    # 형식, 메타데이터, 파일 목록
canvases/2102.canvas.parts/objects/shape.json
canvases/2102.canvas.parts/objects/code.json
canvases/2102.canvas.parts/objects/connector.json
canvases/2102.canvas.parts/permissions.json   # 객체 ID → 그룹 membership
```

종류 파일에는 ID별 객체 내용만, 권한 파일에는 객체의 `permission` 값만 기록한다. 그룹 정의·초대·계정 정보·인증 비밀·캔버스 비밀번호는 내보내지 않는다. 객체 그룹 membership을 파일로 분리하는 것이며 GitHub 저장소 안에서 파일별 읽기 권한을 부여하는 기능은 아니다. 기존 캔버스 내보내기/코드 편집 형식은 v1로 유지하고 저장소 경계에서만 분할/재조립한다.

키를 정렬하여 같은 내용을 안정적으로 직렬화하고, 변경되지 않은 파일은 쓰지 않는다. 마지막 객체가 삭제된 종류의 파일은 같은 커밋에서 제거한다. **분할 파일 변경 검토**에서 파일별 추가·수정·삭제 및 원문을 확인한다. **변경 이력 범위**로 전체/캔버스 구성/종류/객체 권한별 커밋을 조회한다. 파일 범위 조회에서도 복구는 참조 무결성을 위해 커밋 전체 캔버스를 적용한다. 과거 v1 단일 파일 커밋은 전체 이력에서 계속 복구할 수 있다.

GitHub [Trees API](https://docs.github.com/en/rest/git/trees#create-a-tree)로 변경 파일을 하나의 트리에 넣고 커밋한 뒤 [References API](https://docs.github.com/en/rest/git/refs#update-a-reference)의 `force:false`로 브랜치를 갱신한다. 기존 트리를 기반으로 하므로 다른 프로젝트 파일은 유지된다. 현재 파일 SHA와 재조립된 기준 스냅샷을 확인해 인덱스가 그대로인 동안 다른 종류 파일이 변경된 경우에도 덮어쓰지 않는다. 기준 스냅샷이 없는 과거 로컬 초안으로 분할 데이터를 덮어쓰는 것은 거부하며 다시 검토/커밋해야 한다.

완전히 빈 저장소는 Git Database API를 바로 사용할 수 없으므로 먼저 완전한 v1 스냅샷을 초기화 커밋으로 올린 뒤 분할 형식 커밋을 생성한다. 첫 저장만 두 커밋이 생기며, 중간 단계에서 실패해도 초기화 커밋 자체는 읽을 수 있는 캔버스다. 기존 파일의 분할 전환은 한 커밋이다. 사용자의 명시적인 다음 커밋에서 전환하며 과거 커밋은 수정하지 않는다.

읽기는 동일한 커밋 SHA에 고정하여 최대 4개 요청을 병렬 처리한다. 인덱스에 기재된 파일이 없거나 경로가 범위를 벗어나거나 객체 ID가 중복되면 복구를 중단한다. 합계 8MiB 제한을 적용한다. 기본 보존 범위(이미지/PDF 원본, VM 파일 제외), 서버 권한 재검사, 30분 연결 유지와 24시간 토큰 보관은 유지한다.

그래프의 이름 있는 브랜치 열은 현재 브랜치만 표시한다. 이미 병합된 이력은 부모 SHA의 실제 관계에 따라 별도 병합 경로를 사용할 수 있으나, 다른 브랜치 헤드나 미병합 커밋을 불러오지 않는다. 공통 조상으로 향하는 선은 해당 조상 커밋의 점에서 만난다.

커밋은 공통 조상에서부터 부모보다 한 단계 위에 배치하는 방식으로 행을 계산한다. 최신 브랜치 헤드들을 강제로 같은 높이에 놓지 않는다. 분기 후 커밋이 main에 3개, feature에 1개라면 두 브랜치의 첫 커밋이 같은 행에 놓이고 main의 나머지 2개가 그 위에 쌓인다. 병합 커밋은 모든 부모보다 위에 배치하고 짧은 부모 경로의 빈 행은 연결선으로 잇는다. 최신 기록은 위, 오래된 기록은 아래에 유지하며 좁은 화면에서는 가로 스크롤로 브랜치를 탐색한다. 미조회 조상이 있는 구간은 불러온 이력의 경계부터 계산하고 점선으로 구분한다.
