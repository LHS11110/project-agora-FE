# 값 객체와 공유 상태

자료·계산 도구에서 **연속 값**과 **이산 값**을 추가한다. 연속 값은 범위 내 실수를 슬라이더 또는 숫자로 입력한다. 이산 값은 정수, 버튼(0/1), 선택 목록, 문자열을 지원한다. 설정 버튼에서 이름, 종류, 범위, 간격, 선택지를 바꾼다. 이 객체는 값을 표현하며 코드를 실행하지 않는다.

`kind: value`의 `valueType`은 `real`, `integer`, `button`, `select`, `text`다. 숫자는 `valueNumber`, 문자열은 `valueText`, 범위는 `valueMin`, `valueMax`, `valueStep`, 선택지는 `valueOptions`에 저장한다. 서버가 범위와 자료형을 검증하고 기존 객체와 같은 그룹·읽기·쓰기 권한을 적용한다. 범위를 변경하면 현재 값도 새 범위에 맞춰 함께 변경한다.

값, PDF 현재 페이지(`pdfPage`), 영상 재생·일시정지·탐색 상태(`mediaState`), 코드 실행 진행 상태(`runtimeState`), 실행 결과, 문제 답안은 기존 저장 승인 후 브로드캐스팅 경로를 사용한다. 새 참가자는 저장된 최신 상태를 받는다. 실행 상태만 갱신하는 요청은 실행 권한으로 허용하며 내용 수정 권한은 부여하지 않는다. 실행 진행 상태는 undo 이력에 넣지 않는다.

셸 입력·출력과 세션은 사용자별이다. 셸 객체의 위치·크기 등 문서 상태는 공유한다. 음량, 카메라 확대·위치, 패널 배치 및 저장 전 설정 폼은 개인 화면 상태다. 브라우저 자동 재생 정책에 걸린 영상은 해당 기기에서 재생 허용이 필요하다.

## 다른 캔버스 점검

2026-11-04 기준 저장된 4개 캔버스(2102, 2076, 2072, 2096)에 모두 채팅 메타데이터가 있었다. 메타데이터를 원점의 장애물로 취급하던 경로 계산은 공통 drawable 필터로 제외했다. 저장 문서와 권한은 변경하지 않았다.

## 검증

- 프런트엔드 단위 테스트 328개 통과, C++ 브로커 검증 테스트 통과.
- 두 브라우저에서 5종 값, 범위 변경, PDF 페이지, 영상 재생 상태, 실행 상태 및 새로고침 복구 검증.
- 실제 서버에서 사용자·봇 양방향 저장과 전달, 잘못된 범위 거부, 실행 전용 권한 및 잠금 검증.
- 별도 새 봇 참가자가 최신 값·PDF·영상·실행 상태를 초기 문서로 수신함을 검증. 격리된 테스트 계정·봇·캔버스 정리 완료.
- Project Orchestra로 C++와 정적 프런트엔드를 배포하고 운영 도메인의 배포 번들에서도 두 브라우저 공유 테스트 통과(YouTube 외부 API는 테스트 대역 사용).

## YouTube 동기화 보완

선택 도구에서 플레이어를 한 번 클릭해 조작한다. 준비 신호가 늦으면 연결 초기화를 재시도하고, 준비 후 저장된 재생 상태를 적용한다. 직접 조작한 탐색은 반영 억제 구간이 끝난 뒤에도 현재 위치와 공유 위치를 대조해 전달한다. 빠른 연속 조작은 직전 로컬 발행 상태를 기준으로 처리한다. 탐색 슬라이더는 최대 초당 10회와 마지막 위치를 전달하며, 수신한 원격 변경은 아직 대기 중인 이전 탐색을 취소한다.

수신 측 플레이어가 버퍼링 등으로 2.5초 이상 어긋나면 최신 공유 위치로 보정한다. 이 보정은 새 변경으로 재방송하지 않는다. 자동 재생 차단은 각 기기에서 허용해야 하며 실제 재생 시작 시 차단 안내를 해제한다. 프로토콜은 [YouTube 공식 IFrame API](https://developers.google.com/youtube/iframe_api_reference)를 참고한다.

`tests/integration/shared-value-objects.mjs`는 두 캔버스와 YouTube API 대역으로 한 번 클릭 조작, 탐색·일시정지 전달, 직접 탐색의 지연 반영, 수신 플레이어 위치, 시간차 보정 및 재접속 복구를 검증한다. 외부 YouTube 서비스의 실제 재생 가능 여부까지 보장하는 테스트는 아니다.
