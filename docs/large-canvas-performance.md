# 대량 객체 렌더링 검증

2026-10-14, Chrome 155 headless, 1800×1100 화면에서 확인했습니다. 이전 실행은 headless Chrome이 GPU를 기본적으로 비활성화한 상태에서 SwiftShader를 감지한 Canvas 2D 대체 경로를 측정했습니다. 이것은 서버에 GPU가 없다는 의미가 아닙니다. 서버의 RTX 3060 Ti로 확인한 후속 결과는 [60 FPS 검증](canvas-60fps-performance.md)을 참고하세요. GPU 경로는 SwiftShader에서 어댑터 감지를 우회하여 기능만 검증했으며, 하드웨어 GPU 성능 수치로 사용하지 않습니다.

브라우저의 실제 CanvasPage에 12,000개 네이티브 객체를 전달했습니다. 전용 임시 캔버스에서 `init_items` 입력만 테스트 데이터로 대체하고, 브로커의 `canvas_relay` 쓰기를 차단했습니다. 캐시 준비 후 애니메이션 프레임마다 3px씩 이동하는 75개 프레임을 측정했습니다. API 저장 처리량, 최초 네트워크 다운로드 시간, 모든 종류의 문서를 동시에 최대 품질로 렌더링하는 부하를 측정한 결과는 아닙니다.

| 객체 12,000개 시나리오 | 이동 프레임 중앙값 | 95백분위 | 객체용 HTML 요소 |
| --- | ---: | ---: | ---: |
| 개선 전, 한 화면의 반복 도형 | 475.8ms | 653.4ms | 12,000 |
| 개선 후, 한 화면의 반복 도형 | 16.7ms | 34.9ms | 0 |
| 개선 후, 넓게 분산된 도형 | 16.7ms | 41.9ms | 0 |
| 개선 후, 각각 다른 색의 도형 | 16.8ms | 24.8ms | 0 |
| 개선 후, 도형·일반 텍스트 혼합 | 16.7ms | 38.3ms | 0 |
| 개선 후, 읽을 수 없는 작은 코드 객체의 개요 표시 | 16.7ms | 33.9ms | 0 |
| 개선 후, 반복 도형 12,000개 전체 선택 | 16.7ms | 47.2ms | 0 |

[전체 측정 결과](large-canvas-benchmark.json)에 최대 프레임 시간, 캐시 수와 실제 렌더링 객체 수를 보존했습니다. 반복 도형은 래스터 2개와 아틀라스 1장을 공유하며, 12,000개 서로 다른 색의 도형도 아틀라스 3장에 저장됩니다. GPU 기능 검증에서도 12,000개 스프라이트가 아틀라스 1장을 공유했습니다. 프레임 중앙값은 약 60fps에 해당하지만 일부 프레임의 지연은 남아 있으므로 모든 장치와 콘텐츠에서 무지연을 보장하는 수치로 해석하지 않습니다.

Project Orchestra로 배포한 실제 서비스에서도 같은 반복 도형 입력을 확인했습니다. 이동 프레임 중앙값은 20.5ms, 95백분위는 25.6ms였고, 분산된 도형은 각각 17.5ms와 37.3ms였습니다. 로컬 빌드와 배포 검증은 별도 실행이며 측정 때의 서버 부하에 따라 수치가 달라집니다. 배포 후 편집 기능과 픽셀 비교 검증도 통과했습니다.

64개를 넘게 선택하면 벡터 객체의 선택 테두리도 래스터에 그려 객체별 HTML 생성을 피합니다. 12,000개 전체 선택 후 같은 이동 검증을 수행했으며, 선택 표시 전환 시 원본 객체 데이터는 변경하지 않습니다. 단일 객체 편집과 작은 선택은 기존 조작 요소를 사용합니다. 최종 배포에서도 12,000개 전체 선택 시 객체용 HTML 0개, 이동 중앙값 16.7ms, 95백분위 49.1ms를 확인했습니다.

공간 인덱스의 별도 벤치마크는 다음 명령으로 재현합니다.

```bash
node scripts/benchmark-render-index.mjs
node --test tests/*.test.js
```

현재 서버에서 12,000개 객체의 조회 95백분위는 약 0.012ms, 상태 객체 복사를 포함한 단일 이동 갱신은 약 4.2ms였습니다. 50,000개에서도 100회 이동 시 계산한 경계는 100개입니다. 전체 React 렌더링을 포함한 프레임 시간과는 구분합니다.

이전 변경의 전체 Node 테스트 82개가 통과했습니다. 후속 60 FPS 변경은 별도 보고서에 기록했습니다. 브라우저 기능 검증은 텍스트·코드·메모 수정 및 새로고침 후 보존, 겹친 객체의 깊이에 따른 선택, 이동·모서리 크기 조절, 드로잉 선택, 그림체 화살표 선택을 포함했습니다. 그림자와 크기 변경의 부분 갱신 결과는 강제로 전체를 다시 그린 결과와 픽셀 단위로 일치했습니다.

캐시·스프라이트 배칭과 이벤트 처리 축소는 [PixiJS 성능 지침](https://pixijs.com/8.x/guides/concepts/performance-tips), 이미 그린 비트맵의 재사용은 [Canvas 최적화 지침](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas)을 참고했습니다.
