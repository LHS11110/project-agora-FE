# 객체 잠금

객체 선택 → 설정 패널 → 객체 잠금. 선택한 객체가 모두 잠겼으면 버튼이 ‘잠금 해제’로 바뀝니다. 혼합 선택에서는 전체 잠금과 전체 해제를 제공합니다. 편집 권한이 있는 참가자라면 누구나 잠그거나 해제할 수 있습니다. 잠금은 실수 방지 기능이며 ACL/소유권을 대체하지 않습니다.

각 객체 JSON에 boolean `locked`를 저장합니다. 필드가 없으면 잠금 해제로 취급합니다. 도형·연결선·텍스트·코드·표·이미지·드로잉 등 같은 저장 경로를 사용하는 모든 객체에 적용합니다. 별도의 SQL 스키마 변경은 없습니다. 기존의 브로커 → C++ 저장 성공 → 참가자 브로드캐스트 순서를 사용합니다.

잠긴 객체는 선택·복사·댓글·열람이 가능합니다. 이동, 방향키 이동, 크기/회전/곡률 변경, 내용/스타일 수정, 삭제, 잘라내기, 지우개 삭제를 차단합니다. 그룹에 잠긴 객체가 있으면 그룹 회전·그룹 변경을 막습니다. 다중 이동에서는 잠기지 않은 객체만 이동합니다. 선택 상태에서는 잠금 배지를 표시하고 변경 핸들을 숨깁니다. 캔버스 전체 설정, 댓글, 복사는 계속 사용할 수 있습니다.

프런트엔드는 상호작용 시작과 중앙 변경 큐를 모두 검사합니다. 원격 잠금이 도착하면 이전의 낙관적 편집 내용을 화면에 다시 적용하지 않고 진행 중인 내용 편집을 종료합니다. 코드 형태의 캔버스 API 역시 잠긴 기존 객체의 변경·삭제를 먼저 거절합니다. 잠금/해제 패치는 이후 편집 패치와 합치지 않습니다.

C++는 `locked`의 boolean 타입, 이동·삭제·수정과 잠금 해제만 있는 변경을 검사합니다. 잠금 해제와 일반 편집을 한 패치에 섞어 보내면 거절합니다. 권한 검사와 별개로 관리자도 먼저 잠금을 해제해야 합니다. 일반 브로커 저장 경로 및 기존 전체 객체 저장 경로에 동일한 검사를 적용합니다. 댓글은 대상 객체를 수정하지 않으므로 계속 사용할 수 있습니다.

검증:
- `tests/objectLock.test.js`: 변경 거부, manifest 보존/타입, 원격 잠금과 오래된 로컬 편집, 큐 병합, 복사/잘라내기.
- `tests/integration/object-lock.mjs`: 두 브라우저의 잠금/해제, 이동·키보드·삭제·편집 차단, 속성 비활성화, 새로고침 복원. HTTP와 브로커는 격리된 fixture입니다.
- C++ `broker_operations_tests.cpp`, `query_tests.cpp`: 이동/삭제/수정 거부, 명시적 해제, 관리자 및 기존 저장 경로 검사, 드로잉 보호, 원자적 배치 거부와 댓글 허용.
- 배포 환경 임시 캔버스에서도 HTTPS/WSS 저장·브로드캐스트·재접속 복원과 직접 요청의 `ITEM_LOCKED` 응답을 확인했습니다. 임시 데이터는 제거했습니다.
