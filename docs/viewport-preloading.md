# 화면 크기에 맞춘 렌더링 사전 준비

화면 안 객체뿐 아니라 가로·세로 각각 화면 크기의 절반만큼 바깥 영역을 미리 공간 인덱스로 조회하여 렌더링 캐시에 준비한다. 작은 화면의 최소 준비 여백은 각 방향 256px다. 이 값은 화면 픽셀이므로 확대·축소 배율을 적용해 캔버스 좌표로 변환한다. 권한에 따라 전달받은 객체만 대상이다.

장면 범위는 격자 단위로 고정하여 미세 이동마다 바뀌지 않게 한다. 준비 여백의 절반이 남았을 때 새 영역을 조회해 사전 준비를 이어간다. 실제 화면 변환은 브라우저 애니메이션 프레임마다 반영하며 별도 FPS 상한을 추가하지 않는다.

현재 화면의 객체를 우선 래스터화한 뒤 주변 객체를 기존 프레임별 준비 예산으로 처리한다. 현재 화면으로 들어온 이미지의 디코딩은 대기 중인 화면 밖 이미지보다 먼저 수행한다. 텍스트·도형·코드 미리보기는 기존 캐시를 재사용한다. 사전 준비 때문에 코드 실행이나 터미널 연결·영상 재생을 시작하지 않는다.

이미지·PDF 썸네일은 준비 영역의 객체 목록에서 현재 화면 우선, 거리순으로 최대 64개 URL을 선택한다. 대상 선택도 약 2ms 작업 단위로 나누며 공간 인덱스를 별도로 다시 조회하지 않는다. 전송은 3개씩 처리하고 완료되면 다음 대기 항목을 시작한다. 화면 범위가 바뀌면 기존 범위의 아직 시작하지 않은 작업은 취소한다. 다른 소비자와 공유 중인 전송은 완료할 수 있다.

이미지 원본 바이트와 진행 중인 전송은 DOM 이미지·래스터 미리보기 사이에 공유한다. 계정 토큰별 캐시 키, 최대 64개/48MiB 제한과 변경 가능한 표지 이미지 예외를 유지한다. 영상·유튜브 전체를 미리 스트리밍하지 않는다.

검증: `tests/viewportPreload.test.js`는 휴대폰/일반/4K 화면과 여러 배율에서 준비 범위와 공간 검색 대상을 확인한다. `tests/imagePreviewCache.test.js`는 전체 배치의 3개 동시 처리, 중복 전송 방지, 오래된 대기 작업 취소, 현재 화면 이미지의 우선 디코딩을 확인한다.
