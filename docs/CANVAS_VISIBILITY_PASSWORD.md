# 캔버스 공개 범위와 비밀번호

- 비공개: 소유자와 초대된 사용자만 입장한다. 생성·설정 화면에 비밀번호 입력란을 표시하지 않고, 서버도 비밀번호 설정 요청을 거부한다. 기존 비공개 캔버스의 비밀번호는 입장·코드 실행에 요구하지 않는다.
- 공개: 로그인한 사용자가 검색할 수 있으며, 선택적으로 비밀번호를 설정한다. 비밀번호 확인 후 캔버스 접속 토큰을 발급한다. 비밀번호가 있어도 공개 범위와 기본 그룹은 공개 상태로 유지한다.
- 비공개 전환 시 비밀번호를 같은 설정 변경에 포함해 제거한다. 기존 비공개 캔버스를 공개로 바꿀 때도 과거 비밀번호를 되살리지 않는다.
- 캔버스 관리자는 참여자를 초대·강퇴할 수 있다. 강퇴 시 모든 그룹에서 제거하고 설정 버전을 갱신해 기존 접속을 해제한다. 비공개 캔버스에는 다시 초대해야 입장할 수 있다. 소유자는 강퇴할 수 없다.

## 검증 — 2026-11-04

프런트엔드 Node 테스트 314개 통과, 프로덕션 빌드 통과. Spring 테스트 242개 중 239개 통과·환경 조건에 따른 3개 건너뜀, 실패 없음. C++ query/접근 규칙 테스트 통과.

`tests/integration/canvas-visibility-password.mjs`로 생성 화면의 비밀번호 표시·숨김, 비공개 전환 시 입력값 초기화, 공개 비밀번호 설정 및 비공개 전환을 개발 서버와 실제 배포 페이지에서 확인했다. API/WebSocket은 이 브라우저 테스트에서 모의 응답을 사용한다.

별도 임시 사용자 2명과 임시 캔버스로 실제 HTTPS→Spring→브로커→C++ 경로도 검증했다. 공개 캔버스 검색, 비밀번호 누락/오류 거부, 올바른 비밀번호 접속, 비공개 전환, 초대 후 접속, 비관리자 설정 변경 거부, 강퇴 후 기존 세션 차단 및 재입장 거부, 공개 전환 후 비밀번호 재설정을 확인했다.

배포는 Project Orchestra의 운영 계획을 사용해 Spring/C++ 재기동, 정적 프런트엔드 배포, Nginx 및 게이트웨이 검증을 수행했다.

## 재접속 없는 설정 변경

일반 설정(이름·설명·비밀번호)은 `canvas_settings_changed`로 전달하며 연결과 객체 상태를 유지한다. 그룹·참여자·공개 범위 변경은 브로커가 현재 권한을 다시 검증하고 `canvas_access_changed`로 갱신한다. 필요한 객체만 권한에 맞는 스냅샷으로 같은 연결에서 다시 동기화한다. 큐에 남은 요청도 갱신된 권한으로 실행한다. 통화용 peer ID와 연결 증명값은 유지한다. 접근 권한을 잃은 사용자만 연결을 종료한다.

비밀번호 인증은 별도 `password-revision`에 연결하므로 이름·설명 변경으로 무효화되지 않는다. 비밀번호 변경 시에는 기존 인증이 무효화된다. Python SDK 0.1.3도 실시간 권한 갱신과 접근 회수를 처리한다.

최종 검증: Spring 243개(240개 통과·환경 조건 3개 건너뜀), FE 314개, Python SDK 17개. 브로커에서는 설정 변경 후 큐의 권한 갱신, 강퇴 대상만 종료, RTC peer/proof 유지, 변경 도중 접속한 사용자의 최신 ACL 적용, 일시적 저장소 오류 시 연결 유지·재시도를 검사했다. 실제 두 사용자로 반복적인 이름·설명 변경, 객체 표시 권한 회수, 쓰기 차단, 강퇴, 비밀번호 변경 및 인증 유지도 확인했다.
