# 10만·20만·50만 개 객체 검증

아래는 객체 준비 루프 최적화 **이전**의 측정입니다. 수정 후 밀집 장면 전체 준비 결과는 [객체 준비 병목 최적화](canvas-preparation-performance.md)를 참고하세요.

2026-10-14에 배포된 CanvasPage를 NVIDIA RTX 3060 Ti 8GB, Chrome 155, 1800×1100, DPR 1에서 측정했습니다. 모델에 전체 객체를 로드한 뒤 실제 GPU 어댑터와 준비 완료 상태를 확인합니다. 화면 밖 객체를 제외하는 분산 장면과 모든 객체가 화면 안에 있는 밀집 장면을 구분합니다.

분산 장면의 기본 이동·확대·축소는 측정한 모든 프레임이 30 FPS 기준을 통과했습니다. 밀집 장면은 초기 준비가 완료되지 않아 동일한 보장을 할 수 없습니다. 아래 FPS는 준비 완료 이후 카메라 입력을 프레임마다 전달한 브라우저 프레임 간격으로 계산합니다. 준비 중인 부분 장면의 수치를 완성된 장면의 성능으로 계산하지 않습니다.

## 결과

| 전체 객체 수 · 분산 배치 | 이동 평균 FPS | 확대·축소 평균 FPS | 프레임 시간 95백분위 | 최대 프레임 시간 | 로딩·준비 시간 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 100,000 | 60.00 | 60.00 | 17.0ms | 20.3ms | 4.64초 |
| 200,000 | 60.00 | 59.80 | 17.0ms | 31.0ms | 5.88초 |
| 500,000 | 60.00 | 60.00 | 17.1ms | 19.3ms | 8.60초 |

세 장면 모두 모델에 전체 객체가 들어 있는 것을 화면의 총 개수로 확인했습니다. 기본 카메라 위치에서 실제 화면 안에는 80개, 화면 밖 준비 영역까지 포함한 렌더링 대상은 256개입니다. 전체 50만 개를 매 프레임 그린 결과로 해석하면 안 됩니다. 카메라를 이동·확대하면 공간 인덱스가 렌더링 대상을 갱신합니다. 객체용 HTML은 0개였으며 실제 GPU는 RTX 3060 Ti로 확인했습니다.

50만 개 분산 장면의 추가 테스트는 이동 속도를 8배(`PAN_DELTA=24`)로 높여 준비 영역 경계를 반복해서 넘고, 확대·축소도 3배 강하게(`ZOOM_DELTA=1.8`) 하여 각각 600 프레임을 측정했습니다. 평균은 이동 60.00 FPS·확대/축소 60.00 FPS, 95백분위는 모두 17.0ms였습니다. 렌더러는 각 측정에서 599 프레임을 갱신했고 객체 목록 갱신도 발생했습니다. 확대·축소 중 600프레임 중 1개가 39.2ms였으므로 이 추가 테스트는 모든 프레임이 33.33ms 이하인 엄격한 기준에는 미달합니다. 이동의 최대는 19.9ms였습니다.

| 모든 객체가 화면 안에 있는 밀집 배치 | 결과 |
| --- | --- |
| 100,000개 | 120초 준비 제한을 넘김. 이후 부분 준비 상태에서만 이동 프레임을 측정했으므로 정식 FPS 판정에서 제외 |
| 200,000개 | 약 120초 후에도 894개만 준비됨. 전체 장면 FPS 측정 불가 |
| 500,000개 | 약 120초 후에도 256개만 준비됨. 전체 장면 FPS 측정 불가 |

밀집 장면에서 모델의 총 개수와 렌더링 대상 개수는 전체 개수로 일치했지만, 실제 준비된 스프라이트 수와 `preparing` 상태는 완료되지 않았습니다. `DepthVectorLayer`의 초기 준비 루프는 전체 객체를 `Object.entries()`로 매 프레임 다시 열거하며, 열거 시간을 포함한 8ms 예산이 소진되면 신규 객체 대부분을 다음 프레임으로 넘깁니다. 프레임마다 거의 한 개씩만 준비되는 현상을 확인했습니다. 따라서 전체 객체를 한 화면에 표시하는 경우에는 수십만 객체의 30 FPS를 보장할 수 없습니다.

[전체 측정 결과와 렌더러 통계](hundred-thousand-canvas-benchmark.json)에 준비 실패와 지연 프레임을 포함했습니다. 초기 자동화 경유 주입에서 50만 개의 대용량 JSON을 전달했을 때 연결 종료가 발생하여 해당 결과는 성능 판정에서 제외했습니다. 브라우저 안에서 동일한 객체를 생성하도록 측정 방법을 바꾼 뒤에는 50만 개 전체 모델을 정상적으로 로드했고 GPU 렌더링을 확인했습니다. 당시의 연결 종료를 서비스의 렌더러 실패로 판정하지 않습니다.

각 실행에서 객체 1개의 알려진 ID를 100번 이동해 경계를 총 100번만 계산했음을 검증했습니다. 상태 사전 전체를 복사하는 비용은 객체 수에 따라 늘어납니다. 이 결과와 카메라 이동 FPS는 다른 측정이며, 수십만 객체를 로드한 상태에서 객체를 편집·드래그하는 속도까지 검증한 것은 아닙니다.

## 측정 범위

불투명한 기본 사각형 두 색을 사용하며 테두리와 그림자는 끕니다. 분산 배치는 160×120 세계 픽셀 간격에 110×80 크기 객체를 배치합니다. 밀집 배치는 같은 개수의 객체를 1200×700 세계 픽셀 안에 배치하므로 작은 객체도 모두 실제 렌더링 대상으로 포함됩니다. 반복 도형은 텍스처를 공유합니다. 복잡한 텍스트·코드·이미지·그림자·손그림 또는 모든 객체를 동시에 변경하는 경우의 성능 보장은 포함하지 않습니다.

임시 캔버스의 실시간 연결·권한 확인은 실제 서비스에서 수행하고, 최초 `init_items`의 객체만 테스트 데이터로 교체합니다. 최종 측정 스크립트는 객체를 브라우저 안에서 생성합니다. `canvas_relay` 전송을 차단하므로 테스트 객체가 실제 저장소나 다른 사용자에게 전달되지 않습니다. 수십만 객체의 백엔드 저장·네트워크 다운로드 처리량을 측정한 결과는 아닙니다.

기본 이동과 확대·축소는 각각 300 프레임을 측정합니다. 평균 FPS와 프레임 시간 95백분위를 사용하며, 평균 30 FPS 이상·95백분위 33.33ms 이하 여부와, 모든 측정 프레임이 33.33ms 이하인지 여부를 각각 기록합니다. `passes30Fps`는 두 조건이 모두 성립할 때만 참입니다. 최대 지연과 33.33ms를 넘은 프레임 수도 원시 결과에 기록합니다. WebGL 렌더러의 실제 갱신 프레임 수도 함께 기록합니다.

## 재현

[scripts/benchmark-large-canvas-browser.mjs](../scripts/benchmark-large-canvas-browser.mjs)는 기존 서비스의 인증 토큰, 사용자 정보와 전용 임시 캔버스 ID를 환경 변수로 받습니다. `TEMP_CANVAS_ID`를 생성한 전용 캔버스 ID로 설정합니다. 실행 전에 전용 캔버스를 만들고, 실행 후 해당 임시 캔버스를 삭제합니다. 일반 사용자의 기존 캔버스를 테스트 대상으로 사용하지 않습니다.

`playwright-core`가 필요합니다. 설치된 모듈이 있으면 `PLAYWRIGHT_MODULE_PATH`에 `index.mjs`의 절대 경로를 지정할 수 있습니다. `BENCHMARK_TOKEN`에는 유효한 로그인 토큰, `BENCHMARK_USER_JSON`에는 해당 사용자의 로그인 사용자 JSON을 설정합니다. 인증 정보는 결과 파일에 기록하지 않습니다.

```sh
BENCHMARK_URL=https://127.0.0.1 \
BENCHMARK_CANVAS_ID="$TEMP_CANVAS_ID" \
OBJECT_COUNTS=100000,200000,500000 \
BENCHMARK_OUTPUT=/tmp/agora-hundred-thousand-benchmark.json \
node scripts/benchmark-large-canvas-browser.mjs
```

`SCENARIOS=dense` 또는 `SCENARIOS=distributed`로 배치를 제한할 수 있습니다. `PREPARATION_TIMEOUT_MS` 기본값은 120000, `FRAME_SAMPLES` 기본값은 300입니다. 빠른 이동은 `PAN_DELTA=24`, 더 강한 확대·축소는 `ZOOM_DELTA=1.8`로 측정합니다. GPU 어댑터가 실제 GPU인지 결과의 `gpuAdapter`로 확인합니다.

공간 인덱스의 별도 CPU 측정은 다음 명령으로 재현합니다. 이 측정은 화면 FPS를 대신하지 않습니다.

```sh
OBJECT_COUNTS=100000,200000,500000 node scripts/benchmark-render-index.mjs
```
