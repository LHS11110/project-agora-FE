# GitHub 변경 이력과 커밋·푸시

## 그래프

현재 브랜치에서 도달 가능한 커밋(병합한 이력 포함)을 자식이 부모보다 위에 오는 순서로 표시한다. 각 커밋은 한 행을 사용하며 왼쪽의 22px 간격 색상 경로가 실제 부모 SHA를 연결한다. HEAD는 속이 빈 원으로, 일반 커밋은 채운 원으로 구분한다. 브랜치 이름, 메시지, 짧은 SHA, 작성자, 시간을 표시하며 복구·코드 검토 버튼을 유지한다. 불러오지 않은 부모는 점선으로 표시한다.

현재 브랜치 출처 태그를 병합 경로의 소유 브랜치로 간주하지 않는다. 이로 인해 병합 경로가 주 경로로 잘못 합쳐지는 문제를 방지한다. 현재 뷰에서는 이전 병렬 카드용 밴드 계산을 생략한다.

## 수정한 실패 경로

- 여러 로컬 커밋이 동일한 원격 기준 버전을 보유하여 두 번째 푸시부터 충돌하는 문제가 있었다. 푸시 시 최신 스냅샷을 읽고 기준·로컬·원격을 비교한다. 관련 없는 원격 변경은 유지하며 동일 필드의 상충하는 변경은 거부한다. 새 로컬 커밋은 직전 대기 커밋을 기준 버전으로 연결하고 생성 순서로 푸시한다. 따라서 새로 추가한 객체를 연속 수정하는 경우도 처리한다.
- 저장소 대상 객체의 키 순서, 소유자·저장소 대소문자로 인한 잘못된 대상 불일치를 제거했다.
- 검토한 스냅샷은 JSON 키 순서가 아닌 내용으로 비교한다.
- Git 참조 갱신 성공 후 전체 파일을 다시 내려받다가 실패하면 성공한 푸시를 실패로 표시할 수 있었다. 트리에서 반환한 루트 blob SHA 또는 정확한 Git blob SHA-1을 사용해 상태를 준비한 뒤 참조를 갱신한다. 게시 이후의 전체 다운로드는 제거했다.
- 이력 갱신 실패는 커밋·푸시 성공과 별도로 표시한다. 일시적인 실패 시 검토 내용과 연결을 지우지 않는다.
- 서버의 GitHub 권한 조회 실패를 숨기지 않고 표시한다. 실제 GitHub 토큰의 Contents 권한·보호 브랜치·요청 한도 오류를 안내한다.

## 경로와 권한

캔버스의 권한·연결 정책 요청은 기존 WebSocket 서비스 경로를 사용한다. GitHub API는 브라우저가 직접 호출하며 토큰은 브라우저 내에만 저장한다. 각 작업 직전 서버 권한을 다시 확인한다. 원격 참조 갱신은 항상 `force: false`이다. 충돌 시 원격 변경을 덮어쓰지 않는다.

Git 참조 갱신 응답 자체가 유실되는 경우에는 게시 여부가 불확실할 수 있다. 자동으로 다시 커밋하지 않고 GitHub 이력에서 결과를 확인한다. 이번 수정은 성공 응답을 받은 뒤 불필요한 후속 다운로드로 실패 처리하던 문제를 제거한다.

`tests/integration/canvas-github.mjs`는 모의 GitHub와 실제 브라우저 UI로 빈 저장소 초기화, 분할 파일 저장, 그래프, 복구, 충돌, 권한 회수, 로컬 커밋/푸시, 토큰 보관을 확인한다. 테스트는 실제 사용자 저장소에 커밋하지 않는다.
