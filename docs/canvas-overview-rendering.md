# 축소 화면의 텍스트·이미지 미리보기

기존 축소 렌더링은 작은 텍스트와 이미지를 종류별 단색 사각형으로 대체했다. 화면상 짧은 변이 24px 미만이고 면적이 1,200px² 미만일 때 이 경로를 사용한다.

이 경로에서 텍스트는 원래 문자열을 래스터 글자로, 이미지는 실제 내용의 정적 썸네일로 그린다. 확대·선택·편집하면 기존 원본 렌더러로 돌아가며, 저장된 객체 데이터에는 미리보기 필드를 추가하지 않는다. 복잡한 Markdown·코드·수식의 축소 미리보기는 문자열 기반 근사 표시이며 전체 서식은 원본 렌더러에서 표시한다.

이미지 썸네일은 긴 변 최대 96px, 동시 디코딩 2개, 레이어별 캐시 최대 2,048개·800만 픽셀로 제한한다. 같은 이미지 주소의 요청을 합치고 GPU 아틀라스에 복사한 픽셀을 재사용한다. SVG의 ImageBitmap 디코딩을 지원하지 않는 브라우저에서는 이미지 요소로 디코딩한다. 읽을 수 없는 극소 이미지(짧은 변 2px 미만 또는 면적 16px² 미만)는 다운로드 대신 얇은 윤곽으로 표시한다. 로딩 실패도 윤곽으로 처리한다.

이미지 테두리 표시 설정은 썸네일에도 반영한다. 인증 토큰은 동일 API origin에만 전달하며 계정 토큰 변경 시 이미지 캐시를 비운다. 대용량 data URL은 래스터 캐시 키마다 복사하지 않고, 계정 범위와 디코딩 버전으로 구분한다.

줌 배율은 미리보기 선택용으로만 반 옥타브 간격으로 묶는다. 실제 카메라 변환은 연속적으로 적용하며 작은 휠 변화마다 모든 객체의 표현 목록을 재생성하지 않는다. 클릭 판정도 같은 표현 배율을 사용한다.

## 프레임 검증

Chrome에서 1만 개 객체(이미지 5천·텍스트 5천, 서로 다른 이미지 200개)를 1,200×800 화면에 모두 포함하고 약 4~6% 배율에서 비교했다. 캐시 준비 후 각 시나리오 180프레임을 측정했다. 기존 박스 표현과 새 미리보기는 같은 렌더러·배율 버킷을 사용한 비교다. 원격 이미지 다운로드 시간이나 모든 실제 문서의 성능을 보장하는 수치는 아니다.

원시 결과는 [성능 측정 JSON](canvas-overview-performance.json)에 기록한다. GPU와 Canvas 2D 모두 화면 이동 중 추가 래스터 생성은 0회였다. 실제 이미지의 색상과 텍스트 획·투명 배경을 스크린샷 픽셀로 검사하고, 계정 변경 시 썸네일 재요청도 확인했다.

```sh
node --test tests/*.test.js
PLAYWRIGHT_MODULE_PATH=/tmp/agora-depth-check/node_modules/playwright-core/index.mjs \
REQUIRE_GPU=1 node scripts/check-overview-browser.mjs
PLAYWRIGHT_MODULE_PATH=/tmp/agora-depth-check/node_modules/playwright-core/index.mjs \
FORCE_CPU=1 node scripts/check-overview-browser.mjs
```

검증 도구 설치와 로컬 개발 환경은 [브라우저 회귀 검증 안내](canvas-depth-rendering.md)를 따른다. 테스트는 실제 계정·캔버스·저장 데이터를 사용하지 않는다.
