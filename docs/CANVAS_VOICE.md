# 캔버스 음성 통화

채팅·통화는 하나의 패널 안에서 **채팅 / 통화** 탭으로 전환합니다. 상단 **음성 통화** 버튼도 이 패널의 통화 탭을 엽니다. **통화 참여**를 누르면 브라우저의 마이크 권한 요청 후 통화에 참여합니다. 마이크 끄기는 송신 트랙만, 소리 끄기는 이 기기의 수신 오디오만 음소거합니다.

채팅 탭으로 전환하거나 패널을 접어도 통화와 음소거 설정은 유지됩니다. 접힌 패널 버튼과 상단 마이크에 통화 중 표시가 남습니다. 채팅 멘션은 같은 패널의 채팅 탭을 열어 해당 메시지로 이동합니다. 나가기·캔버스 이동·연결 종료 시 마이크 트랙과 모든 피어 연결을 정리합니다. 짧은 RTC/캔버스 소켓 재연결과 동일 계정의 프로필 새로고침은 통화 참여 상태와 기존 마이크, 음소거, 상대방 볼륨을 유지합니다. 복구 중에는 송수신을 멈추고, 인증된 RTC 멤버십을 다시 받은 뒤 자동 복귀합니다. 신호 연결을 60초 안에 복구하지 못하면 마이크를 해제하고 종료합니다. 권한 회수·정책상 연결 종료(1008)·계정 변경·명시적 나가기에는 자동 복귀하지 않습니다.

문서·커서·채팅은 기존 브로커를 사용합니다. 오디오는 참가자 사이의 WebRTC 연결로만 전송하며 서버에서 녹음하거나 저장하지 않습니다. 참가자별 연결을 만드는 mesh 방식이므로 소규모 통화에 적합하며 대규모 회의용 SFU는 포함하지 않습니다.

`voice_state`는 인증된 같은 캔버스의 RTC 멤버에게 참여·음소거 상태만 알립니다. peer ID는 클라이언트 값 대신 서버가 결정합니다. 늦게 입장한 클라이언트는 `rtc_peers`의 `voice_active`·`voice_muted`로 현재 상태를 받습니다. SDP/ICE는 기존 `rtc_signal`로 지정된 피어에게만 전달하며 음성 데이터가 브로커를 통과하지 않습니다.

HTTPS와 브라우저 마이크 권한이 필요합니다. 기본 ICE는 Google STUN을 사용합니다. 대칭 NAT/UDP 차단 환경에서는 STUN만으로 연결되지 않을 수 있으므로 운영 TURN과 단기 자격 증명을 `VITE_WEBRTC_ICE_SERVERS`에 설정하고 프런트엔드를 다시 빌드해야 합니다. 장기 비밀키를 프런트엔드에 넣지 마세요. 기존 예시 설정은 `.env.example`을 참고하세요.

검증: `tests/integration/voice-call.mjs`는 Chrome의 가상 마이크로 실제 WebRTC 오디오 RTP 양방향 수신, 세 번째 참가자의 중도 입장, 음소거와 마이크 종료를 확인합니다. 로컬 Vite 서버에서 실행합니다. `chat-comments-scroll.mjs`는 캔버스의 실제 통화 참여·음소거·나가기 UI를 확인합니다. 브로커 `room_test.exs`는 인증 전 요청 거부, 발신자 위조 방지, 중도 입장 상태와 비영속성을 검증합니다.


각 상대방 아래의 볼륨 슬라이더(0–100%)는 내 기기에서만 적용됩니다. Web Audio GainNode로 음량을 제어하고, 사용할 수 없는 환경에서는 오디오 요소의 볼륨으로 대체합니다. 전체 소리 끄기/켜기는 상대방별 설정을 바꾸지 않습니다. 같은 상대방이 새 RTC ID로 재접속해도 캔버스에 머무는 동안 설정을 유지합니다.

ICE 실패/지속적인 끊김에는 최대 3회의 재협상을 시도하고 실패 시 수동 재시도 버튼을 제공합니다. 충돌하는 양쪽 offer는 [W3C의 perfect negotiation 방식](https://w3c.github.io/webrtc-pc/#perfect-negotiation-example)으로 처리합니다. 새 ICE 세대의 candidate를 별도로 보류하고 이전 세대 candidate는 연결 실패로 취급하지 않습니다. WebSocket 송신 예산이 가득 찼을 때의 신호는 짧게 큐에 보관해 재전송합니다.

추가 검증: 실제 브라우저에서 양방향 RTP, 동시 ICE 재시작, disconnected 상태 주입 후 자동 복구, 신호 송신 일시 거부, 새 RTC ID로 복귀 후 RTP 수신, GainNode 음량 반영을 확인합니다. 캔버스 UI 테스트는 실제 WebSocket을 닫아 RTC/캔버스 소켓 재연결과 프로필 갱신을 유도하며, 통화 유지·볼륨 유지·정책 종료 시 미복귀를 검증합니다.

### 실제 출력 무음 회귀 검증

수신 스트림을 Web Audio에만 연결하면 브라우저에 따라 RTP는 수신하면서 실제 샘플 디코딩/재생은 시작하지 않을 수 있습니다. 수신 `audio` 요소에도 스트림을 설정해 `play()`를 호출하고, Web Audio로 출력하는 동안 이 요소는 항상 `muted=true`, `volume=0`으로 유지합니다. 실제 소리는 GainNode 경로에서만 출력해 중복 재생을 막습니다. 음소거 변경이나 재생 재개에서도 이 원칙을 유지합니다. 관련 비교 구현은 [LiveKit RemoteAudioTrack](https://github.com/livekit/client-sdk-js/blob/main/src/room/track/RemoteAudioTrack.ts)을 참고하세요.

`tests/integration/voice-audibility.mjs`는 임시 PCM 사인파를 마이크 입력으로 생성하고 실제 두 WebRTC 피어 사이에 전송합니다. 수신 패킷 수만 확인하지 않고 GainNode 전후의 출력 신호 RMS를 측정합니다. 출력의 비영점 여부, 상대방별 볼륨 비율, 전체 수신/마이크 음소거와 해제, ICE 재협상 및 인증된 방 재접속 후 출력 복구, 중복 출력 방지와 종료 시 재생 해제를 검증합니다. 임시 오디오 파일은 테스트 후 삭제합니다.

`tests/integration/voice-canvas-output.mjs`는 실제 캔버스 화면 두 개를 별도 브라우저 컨텍스트에서 열어 위 검증을 수행합니다. API/브로커 신호는 테스트 방으로 격리하며, 캔버스 앱의 실제 코드와 브라우저 WebRTC로 오디오를 송수신합니다. 자동 재생 제한을 해제하는 플래그 없이 UI의 참여 버튼으로 통화를 시작하고, 출력 신호·볼륨·전체 음소거·중복 출력 방지·종료 해제를 확인합니다. 운영 번들에서도 `AGORA_E2E_ORIGIN`을 지정해 실행할 수 있습니다.
