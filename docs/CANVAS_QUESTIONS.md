# 문제 객체

툴 패널의 **자료·계산 → 문제 객체**를 선택한 뒤 캔버스에 놓습니다.

1. **문제 수정**에서 객관식(하나 선택) 또는 주관식을 선택합니다.
2. 문제 내용, 객관식 보기 2~10개, 배점 1~1,000점을 작성하고 **문제 저장**을 누릅니다.
3. **공동 답안**에서 보기를 선택하거나 주관식 답안을 입력한 뒤 **답안 제출**을 누릅니다.
4. 쓰기 권한이 있는 사용자가 **직접 채점**에서 점수와 피드백을 입력하고 **채점 저장**을 누릅니다. 자동 채점이나 정답 추론은 하지 않습니다.

문제당 답안 하나를 참가자들이 공유합니다. 개인별 시험 제출함이 아닙니다. 입력 중인 문구는 로컬 초안이며 저장·제출 버튼을 누르면 기존 브로커 → C++ 저장 → 브로드캐스팅 경로로 공유합니다. 새 참가자와 재접속한 참가자는 저장된 문제·답안·점수·피드백을 받습니다.

주관식에서 객관식으로 바꿀 때 보기가 아직 비어 있어도 유형 변경을 저장할 수 있습니다. 모든 보기를 채우기 전에는 답안을 제출할 수 없으며 카드에 안내를 표시합니다.

문제를 저장하면 기존 공동 답안과 채점이 초기화됩니다. 답안을 다시 제출하면 기존 점수와 피드백이 초기화됩니다. 제출된 답안 버전과 채점 대상 버전이 다르면 서버가 채점 요청을 거부합니다. 오래된 답안의 점수가 새 답안에 적용되지 않습니다.

읽기 전용 참가자는 내용을 볼 수 있지만 문제 수정·제출·채점은 할 수 없습니다. 해당 객체의 그룹별 쓰기 권한과 잠금은 기존 서버 규칙으로 강제합니다. 출제자에게만 채점권을 제한하는 별도 역할은 없습니다.

문제 객체는 이동·크기 조절·깊이·그림자·모서리 설정·미니맵·선택·복사·Undo 및 캔버스 JSON 가져오기/내보내기에 통합되어 있습니다. 작은 화면상의 객체는 기존 개요 렌더링과 화면 밖 객체 제외 정책을 사용합니다.

## 데이터와 API

`kind: "question"`이며 기존 객체 생성·수정 API를 사용합니다.

| 필드 | 설명 |
| --- | --- |
| questionType | `choice` 또는 `short-answer` |
| questionPrompt | 문제 내용, 최대 4,000자 |
| questionOptions | 보기 배열, 2~10개, 각각 최대 300자; 주관식에서는 사용하지 않음 |
| questionAnswer | 공동 답안; 객관식은 0부터 시작하는 보기 번호 문자열, 주관식은 최대 8,000자 |
| questionSubmitted | 제출 여부 |
| questionMaxScore | 배점, 정수 1~1,000 |
| questionScore | 미채점은 -1, 채점 점수는 0~배점(소수점 허용) |
| questionFeedback | 최대 2,000자 |
| questionVersion | 문제·답안 변경마다 새로 발급하는 최대 128자 버전 문자열 |
| questionGradedVersion | 채점 대상 버전; 채점 시 questionVersion과 같아야 함 |

프런트엔드 생성·검증·초기화 함수는 `src/canvas/questions/questionData.js`에 있습니다. SDK를 사용할 때도 모든 필드를 초기화해야 하며, 문제·답안·배점·제출 여부 변경 시 새 questionVersion을 함께 전달해야 합니다. 채점 시 questionScore, questionFeedback, questionGradedVersion만 수정합니다. 서버는 버전·점수·보기 및 제출 데이터의 일관성을 검증합니다. 기존 버전을 이용한 새로운 내용 수정은 `QUESTION_REVISION_REQUIRED`, 오래된 버전 채점은 `QUESTION_GRADING_STALE`로 거부합니다.
