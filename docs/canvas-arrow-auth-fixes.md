# 화살표 직선화와 인증 오류 수정

## 조절점 배열 검증

3개 조절점이 있는 일반 화살표를 직선화할 때, 이전 구현은 `bendPointCount: 1`과 `bendPoints` 삭제를 함께 보냈다. 호스트는 삭제를 적용한 뒤 manifest 검증에서 이전 객체를 다시 병합해 길이가 3인 배열을 되살렸고, 조절점 수와 배열 길이가 다르다는 오류로 변경을 거절했다.

호스트 검증은 변경된 객체의 최종 상태를 사용한다. 삭제·연결 종속성 검증에는 필요한 기존 객체 정보를 유지한다. Canvas as Code의 사용자용 병합 의미는 바꾸지 않는다.

일반 화살표 직선화는 기존 조절점 수를 유지하며 각 조절점을 시작점과 끝점 사이의 직선에 정렬한다. 따라서 직선화 뒤에도 세 점을 각각 다시 드래그할 수 있다.

## `/api/auth/me` 401

사용자 보고 직후 조회한 서버 로그의 가장 최근 해당 요청은 `AUTH_004`와 `SecurityException`으로 기록됐다. JWT 필터의 이 경로는 토큰 발급 당시 IP와 현재 IP가 다른 경우다. 이 토큰은 재로그인이 필요하다.

서버는 IP 변경 시 JSON의 `reason: CLIENT_IP_CHANGED`와 재로그인 안내를 반환한다. 클라이언트는 안내를 표시하고 현재 로그인 토큰의 실패만 처리한다. 이전 로그인 요청의 늦은 401이나 별도 캔버스 접근 토큰의 401은 새 로그인 세션을 제거하지 않는다. 만료됐거나 형식이 잘못된 저장 토큰은 `/api/auth/me` 호출 전에 정리한다. 재로그인 후 원래 화면으로 돌아간다.

## 검증

- Node 테스트 131개: 필드 삭제의 최종 상태 검증, 3개 조절점 직선화 후 재편집, 두 사용자 간 승인·동기화·저장 포함.
- Spring JWT 필터 테스트: 변경 IP는 구조화된 401, 현재 IP 토큰은 인증 진행.
- 브라우저: 만료 토큰, IP 변경 안내, 이전 요청의 늦은 401, 캔버스 토큰 401을 별도로 검사. 실제 계정 및 저장 데이터는 사용하지 않는다.

```sh
node --test tests/*.test.js
PLAYWRIGHT_MODULE_PATH=/tmp/agora-depth-check/node_modules/playwright-core/index.mjs \
node scripts/check-auth-session-browser.mjs
```

브라우저 검증 도구 설치와 로컬 개발 환경 요건은 [깊이 렌더링 검증](canvas-depth-rendering.md)을 따른다.

배포 후 실제 HTTPS 게이트웨이에서도 변경 IP 토큰은 `401 / CLIENT_IP_CHANGED`, 현재 IP 토큰은 `/api/auth/me`의 `200` 응답을 확인했다. 검증은 기존 계정 정보를 조회하는 요청만 사용했으며 사용자 데이터는 변경하지 않았다.
