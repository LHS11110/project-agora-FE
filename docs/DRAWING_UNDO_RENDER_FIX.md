# 드로잉 undo·지우개 전환 렌더링 수정

2026-11-04에 실제 브라우저에서 두 문제를 재현하고 수정했다.

## 원인

`useServerCanvas`는 window의 pointerup 캡처 단계에서 microtask로 undo 그룹을 닫았다. 브라우저는 이 microtask를 React의 pointerup 핸들러보다 먼저 실행할 수 있다. 그 결과 드로잉 프레임들과 마지막 `complete: true` 변경이 서로 다른 기록으로 남았다. 재현에서는 선 하나에 기록이 2개 생겼고, undo를 한 번 누르면 선이 삭제되지 않고 `complete: false` 상태로 돌아갔다.

드로잉의 선택 판정용 SVG는 `select-mode`일 때만 `fill: none`을 적용했다. 선택된 선을 유지한 채 지우개로 전환하면 SVG polyline의 기본 채우기(검정)가 활성화되어 내부가 채워졌다. 실제 브러시의 채우기 설정이나 저장된 드로잉 데이터가 변경된 것은 아니었다.

## 변경

- 포인터 종료 처리 뒤에 undo 그룹을 닫는다. 다음 제스처가 시작되면 이전 종료 타이머를 취소해 새 기록이 잘리는 것을 방지한다.
- Ctrl+Z 또는 도구 바 undo는 진행 중인 드로잉·지우개 제스처를 먼저 마치고 대기 프레임을 반영한 뒤 취소한다. 후속 포인터 이동으로 취소한 선이 다시 생기지 않는다.
- 지우개 제스처의 포인터 ID를 유지해 취소 시 해당 포인터 캡처를 해제한다.
- 선택 판정용 SVG와 그 자식의 채우기·선 색을 모든 도구에서 투명하게 유지한다. 선택 모드에서만 hit testing을 활성화한다.

기록 개수 제한이나 공동 편집 텍스트 undo의 충돌 보호 규칙은 변경하지 않았다.

## 검증

- Node 테스트 317개 통과.
- `tests/integration/drawing-undo.mjs`: 빠른/느린 반복 드로잉, 선 하나당 기록 1개, 부분 지우기 undo와 조각 제거, pointercancel, 드로잉/지우개 도중 Ctrl+Z, 도구별 투명 SVG 확인.
- 기존 `canvas-undo.mjs`: 제한 없는 기록, 여러 객체 이동 묶음, 타 사용자 필드 보존, 공동 텍스트·색상·삭제 복원, 권한 검사 통과.
- `drawing-undo-live.mjs`: 실제 두 사용자와 HTTPS/브로커/C++ 저장 경로에서 진행 중 선 공유, undo 삭제 공유, 지우개 undo 복원, 재접속 후 삭제 유지 확인. 테스트용 계정·캔버스만 사용했다.

프런트엔드 Docker 이미지를 빌드하고 Project Orchestra의 정적 릴리스 배포 절차로 운영에 반영했다.
