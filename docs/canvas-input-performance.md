# 드로잉·텍스트 입력 프레임 개선

2026-10-14 측정. 입력마다 전체 객체 맵 복사, 호스트의 전체 객체 조회·검증, 협업 문서 재해석, 장면·미니맵 재생성이 겹쳐 정적인 장면보다 편집 중 프레임이 크게 떨어졌다.

## 변경

- 객체 스냅샷은 변경된 버킷만 복사한다. 호스트의 낙관적 재적용, 변경 비교, 그래프 검증도 영향받은 객체와 연결선만 처리한다. 권한 검사와 원자적 거절은 유지한다.
- 협업 문서와 직렬화 결과를 캐시하고 승인 문서는 복제해서 편집한다. 같은 객체의 연속 텍스트 제안은 새 문서가 이전 변경 이력을 포함할 때만 병합한다. 독립적인 동시 편집은 그대로 처리한다.
- 진행 중인 드로잉은 별도 잉크 표면에서 프레임 단위로 그린다. 정적인 GPU 장면은 매 좌표 갱신마다 준비하지 않는다. 완료된 선은 일반 객체로 전환한다.
- 장면, 공간 조회, 미니맵과 패널 집계는 변경 ID를 이용해 재사용한다. 미니맵의 전체 재생성은 여러 프레임으로 나눈다.

## 측정

Chrome 155, RTX 3060 Ti, 실제 NVIDIA ANGLE/WebGL, 1800×1100, DPR 1, 화면 안에 모든 객체가 포함된 장면이다. 혼합 장면은 1,500개 중 약 500개가 일반 텍스트다. 10만 장면은 기본 사각형 배경과 편집 대상 객체로 구성한다.

| 장면·동작 | 수정 전 평균 FPS | 수정 후 평균 FPS | 수정 후 p95 프레임 | 최대 프레임 | 33ms 초과 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1,500 혼합 · 텍스트 | 8.4 | 59.1 | 22.1ms | 73.8ms | 1/300 |
| 1,500 혼합 · 드로잉 | 10.1 | 60.0 | 20.3ms | 20.9ms | 0/60 |
| 100,000 · 텍스트 | 미측정 | 58.8 | 23.1ms | 83.2ms | 2/300 |
| 100,000 · 드로잉 | 미측정 | 58.8 | 22.4ms | 80.9ms | 4/300 |

수정 전 비교는 각각 60프레임, 수정 후 텍스트와 10만 객체는 300프레임이다. 동일한 1,500개 장면에서 프레임당 실제 입력 경로를 호출했다. 텍스트 최종 저장 내용은 마지막 입력값과 같고, 완료된 드로잉은 각각 61개·301개 좌표를 포함한다.

이는 브라우저 rAF 간격 측정이며 GPU 작업 완료 시간 측정은 아니다. 성능 측정에서는 실제 WebSocket 초기 데이터를 브라우저 안에서 테스트 객체로 대체하고 저장 ACK를 모의 처리한다. 실제 네트워크 저장 지연은 포함하지 않는다. 객체 준비 후 도구와 편집기를 연 상태에서 측정하므로 최초 선택·도구 전환·선 완료 시 전체 장면 준비 비용도 별도다. 간헐적인 긴 프레임이 남아 있으며 모든 콘텐츠·기기에서 60 FPS를 보장하지 않는다. 연결선이 많은 장면의 경로 재계산은 추가 측정 대상이다.

원본 측정은 [canvas-input-benchmark.json](canvas-input-benchmark.json)에 있다. sourceRevision은 기준 커밋이며 이번 변경은 작업 트리에서 검증했다.

Project Orchestra의 production 정적 exporter로 빌드하고 원자적 release 링크를 교체했다. 실제 배포 주소에서 같은 10만 객체 장면을 다시 측정한 결과, 텍스트 평균 58.2 FPS(p95 24.2ms, 최대 90.6ms, 33ms 초과 3/300), 드로잉 평균 60.0 FPS(p95 23.9ms, 최대 40.8ms, 33ms 초과 1/300)였다. 이 재측정은 로컬 프런트엔드 대체 없이 배포된 자산을 사용했고 저장 ACK 모의 조건은 동일하다.

## 검증·재현

- Node 테스트 102개 통과: 스냅샷 불변성, 전체 순회 방지, 협업 문서 재사용, 승인 이력 보존, 독립 편집 병합, 삭제·연결선 제약, 권한 및 동기화 회귀 테스트.
- 실제 백엔드에서 텍스트·코드·포스트잇 저장 후 새로고침, 깊이 선택, 이동·크기 변경, 드로잉 선택, 손그림 화살표 선택을 확인했다.
- 배포된 서비스에서 실제 마우스로 그린 25개 좌표의 완료된 선이 백엔드 저장 후 새로고침에서도 유지됨을 확인했다.
- 12,000개 서로 다른 색상 객체의 GPU 표시와 WebGL 손실 후 Worker 표시에서 표본 색상이 일치했다. CPU 폴백에서 1,000개 객체 중 하나를 이동·회전·그림자 수정한 부분 갱신은 전체 갱신과 픽셀 차이가 0이다.

브라우저 측정은 `scripts/benchmark-large-canvas-browser.mjs`를 사용한다. 인증 환경 변수 설정은 스크립트 상단을 참고한다. `BENCHMARK_WORKLOAD=text` 또는 `draw`, `OBJECT_COUNTS=1500,100000`, `SCENARIOS=dense`, `FRAME_SAMPLES=300`으로 실행한다. `MIXED_TEXT=1`은 혼합 장면을 만든다. 테스트 저장은 모의 처리하지만 캔버스는 별도의 임시 캔버스를 사용한다.
