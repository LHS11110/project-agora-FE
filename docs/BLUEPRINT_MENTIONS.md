# 블루프린트 실행과 멘션

## 블루프린트 사용

툴 패널의 **자료·계산**에서 실행 객체, 코드 객체, 실행 결과 객체를 배치합니다.
연결 도구로 `실행 객체 → 코드 객체 → 실행 결과 객체` 방향의 화살표를 만듭니다.
코드 객체를 두 번 클릭해 언어와 코드를 편집한 뒤 실행 객체의 **코드 실행**을 누릅니다.
코드를 수정하는 것만으로는 실행되지 않습니다. 일반 연결 화살표의 `from → to`를 사용합니다.

여러 코드 객체는 연결 순서에 따라 한 번씩 실행되며, 한 코드에 여러 결과 객체를
연결하거나 결과 객체끼리 연결해 같은 출력을 여러 위치에서 볼 수 있습니다.
순환 연결은 실행 전에 거부합니다. VM 실행 실패·시간 초과가 발생하면 후속 코드 실행을
중단하고 연결된 결과 객체에 오류를 표시합니다.

Python, JavaScript, C, C++, Shell을 지원합니다. NAT 아웃바운드를 허용하는 캔버스별 VM의
파일 공간과 언어별 실행 환경을 공유합니다. 같은 언어에서는 변수, 함수, 객체와 변경된
값이 다음 코드 객체뿐 아니라 **실행 버튼을 다시 누른 이후에도** 유지됩니다. 이전 코드를
재실행하거나 소스를 합쳐 상태를 복원하지 않습니다. 다른 언어 사이에는 메모리 변수를
직접 공유하지 않으며 `/workspace`의 파일로 데이터를 교환할 수 있습니다.

셸 코드 객체에서 `pip install 패키지명`을 실행할 수 있습니다. 패키지는
`/workspace/.python`에 설치되고 Python 검색 경로에 반영되며 VM 재시작 후에도
유지됩니다. 외부에서 시작한 연결과 호스트·사설망·다른 VM 접근은 차단합니다.
패키지 설치에도 코드의 15초 실행 제한과 저장 용량 제한이 적용됩니다.

실행 객체의 **실행 환경 초기화**는 해당 캔버스의 모든 언어 변수를 초기화합니다.
저장 파일과 기존 결과 객체는 유지됩니다. 참여자들은 같은 환경을 공유합니다.
C/C++은 Clang의 증분 컴파일러를 사용합니다. 변경되지 않은 코드 객체를 반복 실행하면
기존 변수·함수·타입 선언과 JIT 기계어를 재사용합니다. 최초 컴파일에서 생성된
실행문 함수와 `main`의 주소를 캐시해 직접 호출하며 같은 소스는 재컴파일하지 않습니다. 전역 변수의
최초 초기화는 한 번만 수행하므로 반복 실행 사이에 변경된 값이 보존됩니다.
`main` 본문을 수정하면 새 실행 주소로 컴파일하며 이전 버전의 캐시도 유지됩니다.
같은 셀의 `main` 바깥 코드가 동일하고 최상위 실행문이 없는 경우, 기존 전역 선언을
재사용해 값이 초기화되지 않도록 합니다. 컴파일 오류는 이전 상태를 유지한 채 반환하며
누락된 함수를 추가하거나 코드를 수정해 다시 실행할 수 있습니다. `main` 외의 선언을
수정해 같은 이름을 다시 정의하는 경우에는 실행 환경 초기화가 필요할 수 있습니다.
JavaScript의 `let`·`const`도 재선언 시 오류가 날 수 있으므로 기존 변수에 대입하거나
환경을 초기화하세요.

환경은 VM 메모리에 보관되므로 VM 재시작, 15분 유휴 종료, 시간·출력·메모리 제한 또는
인터프리터 종료 시 초기화됩니다. 실행 중 장애로 초기화되면 결과 객체에 표시됩니다.
일반적인 코드 예외는 이전까지의 상태를 유지하고 후속 객체 실행만 중단합니다.
 실행 그래프와 코드는 버튼을 누른 시점의 스냅샷을 사용하고,
실행 중 연결이 제거된 결과 객체에는 새 출력을 쓰지 않습니다.

한 번의 실행은 코드 최대 32개, 그래프 객체 최대 256개입니다. 결과 객체당 최근 실행
결과를 최대 32개, 직렬화 크기 512KiB 내에 보관합니다. 결과는 일반 캔버스 변경처럼
브로커와 C++ 서버를 통해 저장·공유되며 재접속 후에도 보입니다. 연결하지 않은 결과
객체에는 출력을 전달하지 않습니다. 결과 객체에는 마지막으로 저장된 결과가 유지됩니다.

## 서버가 관리하는 멘션

채팅과 객체 댓글에서 `@`로 닉네임과 태그 번호를 선택합니다.
서버는 실제 계정과 현재 캔버스·객체 권한을 검증해 멘션 대상을 확정합니다.
메시지의 `mentions[userId]`는 미읽음 `true`, 읽음 `false`입니다.
메시지와 사용자별 알림 인덱스는 같은 Redis 원자 작업으로 기록됩니다.
요청 재시도는 동일 메시지를 중복 추가하거나 읽음을 다시 미읽음으로 바꾸지 않습니다.

알림은 서버의 `mentions_get` 응답으로만 표시합니다. 알림을 눌렀을 때 해당 내용을
불러와 표시한 뒤 `mention_read`를 전송합니다. 알림 닫기도 읽음 처리합니다.
클라이언트의 로그인 ID 대신 인증된 브로커 세션의 사용자 ID로만 조회·변경합니다.
다른 탭과 기기에는 서버의 변경 신호를 전송하고, 재접속 시 다시 조회합니다.
세션 저장소나 로컬 저장소에 읽음 상태를 보관하지 않습니다.

오래된 멘션은 sequence 주변 메시지를 조회해 이동합니다. 객체 권한이 변경되거나 객체가
삭제되면 해당 댓글 알림은 조회 결과에서 제외합니다. 화면에는 최근 미읽음 최대 100개를
표시하고 읽은 알림이 제거되면 다음 알림이 조회됩니다. 현재 캔버스의 멘션을 표시합니다.
영구 스냅샷에는 사용자별 알림 상태를 `mention-states-b64`로 인코딩해 저장합니다.

## 검증

`node --test tests/*.test.js`와 C++ 브로커 검증·스냅샷·멘션 단위 테스트를 실행합니다.
실제 Redis 검증은 BE의 `python3 cpp/tests/mentions_redis_integration.py`를 사용하며
임시 키를 생성하고 정리합니다.

`tests/integration/blueprint-mentions.mjs`는 배포된 HTTPS 서비스에서 두 테스트 계정과
**전용 임시 캔버스**를 사용하는 실제 브라우저·VM 테스트입니다. 다음 환경 변수가 필요합니다.

- `AGORA_E2E_STATE`: 권한 0600 JSON 파일 경로. `{sessions:[{token,user},{token,user}], complete_id:임시캔버스ID}` 형식.
- 두 번째 계정은 임시 캔버스에 초대되어 있어야 합니다.
- `AGORA_E2E_PLAYWRIGHT_MODULE`: 설치된 playwright-core의 index.mjs 절대 경로.
- `AGORA_E2E_ORIGIN`: 배포 주소. 기본 `https://localhost`.
- `AGORA_E2E_CHROME`: Chrome 실행 경로. 기본 `/usr/bin/google-chrome`.

테스트는 임시 캔버스에 객체·댓글·메시지를 생성합니다. 실행 후 임시 캔버스를 삭제합니다.
토큰과 계정 상태 파일은 저장소에 추가하지 않습니다.

`tests/integration/blueprint-environment.mjs`는 빈 임시 캔버스에서 코드 간 변수·함수
상속, 반복 실행, 브라우저 새로고침, 초기화 버튼과 두 브라우저 결과 공유를 검증합니다.
`AGORA_E2E_STATE`는 `{token,user,canvas_id}` 형식의 권한 0600 파일이며, 나머지
브라우저 환경 변수는 위와 같습니다. 필요한 경우 `AGORA_E2E_HOST_RESOLVER`에
Chrome의 host resolver rule을 지정합니다. 이 테스트는 기존 객체가 있는 캔버스를
거부하며 완료 후 운영자가 임시 캔버스와 해당 VM 디스크를 정리합니다.

선택된 실행 결과 객체의 본문에서 휠을 움직이면 결과 내부가 스크롤됩니다.
선택되지 않은 결과 객체 위에서는 휠로 캔버스를 이동합니다. 스크롤 끝에
도달해도 캔버스가 움직이지 않습니다. 캔버스의 두 손가락 제스처는 손가락 중심을
기준으로 확대·축소와 이동을 수행하며 한 손가락 필기와 펜 입력은 유지합니다.
`tests/integration/touch-navigation.mjs`는 Vite의 `tests/browser/touch-navigation.html`
화면에서 실제 휠·멀티터치 이벤트를 검증합니다. 브라우저 모듈·주소는 위의
`AGORA_E2E_PLAYWRIGHT_MODULE`, `AGORA_E2E_ORIGIN`을 사용하며, 로컬 개발 인증서에만
필요한 경우 `AGORA_E2E_INSECURE_LOCAL_TLS=1`을 지정합니다.

### 선택한 코드의 빠른 실행

코드 객체 하나를 선택하고 **Shift + Enter**를 누르면 그 코드만 실행합니다.
실행 객체를 따로 만들 필요는 없으며, 다른 코드 객체로 연결된 선이 있어도 선택한
코드만 실행합니다. 실행 결과는 해당 코드에 연결된 결과 객체와 이어진 결과 객체들에
기존 방식으로 저장·공유합니다. 연결된 결과 객체가 없으면 실행 완료/오류를 알립니다.

코드 편집 중에도 최신 내용을 실행하고 줄바꿈을 삽입하지 않습니다. 편집기를 닫지
않으므로 바로 수정을 이어갈 수 있습니다. VM 변수·함수는 기존 언어별 환경을 사용합니다.
키를 길게 누르거나 실행 중 다시 눌러도 중복 실행하지 않습니다. 채팅·설정·다중 선택·
IME 입력 중에는 코드 실행 단축키를 적용하지 않습니다.

### 코드 자동완성 표시

자동완성은 편집기와 같은 어두운 색상으로 표시하며, 함수·타입·키워드·템플릿·현재 코드의 이름을 아이콘과 분류로 구분합니다. 템플릿의 코드 미리보기와 설명을 펼쳐 확인할 수 있고, Tab으로 삽입한 뒤 다음 입력칸으로 이동합니다. 팝업은 캔버스 배율과 독립적으로 일정한 크기를 유지합니다. JavaScript 등 Monaco가 지원하는 언어는 기본 언어 서비스의 제안을 사용하며, 다른 언어의 기본 제안이 전체 언어 서버를 대체하지는 않습니다.
