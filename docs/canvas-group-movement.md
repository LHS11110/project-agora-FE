# 다중 객체 이동 전송

선택한 객체 여러 개를 드래그할 때는 객체별 위치 패치 대신 하나의 상대 이동 변경을 제출한다.

```json
{"action":"translate","ids":["shape-a","text-b","stroke-c"],"dx":0.01,"dy":-0.02}
```

`dx`, `dy`는 캔버스 세계 좌표의 정규화된 이동량이다. 브로커가 이 제안을 현재 호스트로 전달하고, 호스트가 객체 존재와 권한을 원자적으로 검사한 뒤 승인된 이동량을 참가자에게 전달한다. 승인 메시지는 접근 가능한 ID 목록·이동량과 순서·버전·요청 확인용 메타데이터를 포함한다. 텍스트 문서, 이미지 데이터, 드로잉 좌표와 객체 스타일은 전송하지 않는다. 드로잉의 각 점 이동은 수신 측에서 계산한다.

이동만 대기 중이면 요청 생성 간격은 100ms다. 같은 ID 목록의 연속 대기 이동량은 합산하고, 드래그 종료 시 마지막 포인터 위치를 반영해 즉시 전송을 요청한다. 승인 대기나 연결 중단 중에도 마지막 이동량을 보존한다. 다른 종류의 편집은 기존 순서를 유지한다. 회전과 크기 변경은 기존 변경 경로를 사용한다.

순서 번호로 누락과 중복을 검사한다. 승인 메시지가 요청 ACK보다 먼저 도착해도 이미 적용된 상대 이동을 낙관적 화면에 다시 적용하지 않는다. 호스트 교체 시 요청 카운터로 재시도를 중복 처리하지 않는다. 신규 참가자는 승인된 최신 절대 위치의 전체 스냅샷으로 시작한다. 저장소에는 기존 형식의 최종 객체를 저장하므로 저장 후 새로고침에도 적용된다.

지원 여부는 호스트 준비 메시지와 클라이언트 등록에서 협상한다. 이전 버전의 호스트·참가자에게는 기존 위치 패치·전체 승인 레코드를 사용한다. 한 이동 변경의 ID 목록은 최대 10,000개이며, 중복 ID·비정상 이동 벡터·삭제된 객체·권한 없는 객체는 거절한다.

검증: Node 테스트 113개 통과. 실제 브로커에 두 브라우저 클라이언트를 연결해 도형 2개·텍스트·드로잉을 함께 120px, 80px 이동했다. 연속 입력 25개를 묶은 실행에서 승인 메시지 2개, 최대 전체 전송 메시지 603바이트로 확인했다. 수신 위치·내용·펜 압력이 유지되고 실제 백엔드 저장 후 새로고침에서도 위치가 유지됐다. 단위 테스트는 10만 문자 이미지 데이터를 포함한 객체 그룹에서도 제안과 승인 메시지 각각 1KB 미만임을 확인하며, 동시 이동·권한 필터·원자적 거절·중복 메시지·ACK 순서·신규 참가자·호스트 교체를 검증한다.

Project Orchestra로 production 정적 프런트엔드를 배포한 후 실제 배포 주소에서도 두 클라이언트 검증을 반복해 통과했다. 이 실행에서는 연속 입력 25개가 598바이트 승인 메시지 1개로 전달됐고 최종 위치·내용·저장 후 새로고침이 일치했다.
