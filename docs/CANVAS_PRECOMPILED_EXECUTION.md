# 사전 빌드 실행

캔버스의 **실행 환경 → 언어 → 실행 방식 → 사전 빌드 후 실행**을 선택하고 적용합니다.
코드 객체의 **사전 빌드** 또는 실행 객체의 **사전 빌드**로 준비한 후, 기존 실행 버튼이나 Shift+Enter로 실행합니다.
실행 객체의 빌드는 연결된 코드들을 위상 정렬 순서로 빌드합니다. 기존 실행 모드의 코드는 건너뜁니다.

| 언어 | 준비 결과 | 실행 |
| --- | --- | --- |
| C / C++ | 선택한 Clang 또는 GCC의 네이티브 실행 파일 | 실행 파일 직접 실행; `main` 필수 |
| Java | 선택한 JDK의 `javac`가 만든 클래스 파일 | `java`로 main 클래스 실행; Maven 의존성 포함 |
| Python | 선택한 CPython 버전의 `.pyc` | 같은 인터프리터로 바이트코드 실행 |
| JavaScript | 선택한 Node/V8 버전의 코드 캐시 | 캐시로 실행; 실행 중 JIT 최적화 가능 |
| Shell | `bash -n`으로 검사한 스크립트 | Bash 인터프리터로 실행; 컴파일 언어가 아님 |

사전 빌드는 프로그램을 실행하지 않고 컴파일 오류는 해당 코드 블록의 빨간 테두리와 실패 표시로 안내합니다. 실패 표시를 누르면 상세 내용을 확인할 수 있습니다. 기존 결과 객체는 유지됩니다.
실행은 빌드를 자동 수행하지 않습니다. 코드·언어·컴파일러·옵션이 바뀌면 다시 빌드해야 합니다.
실패하거나 시간 제한을 넘긴 빌드는 실행 대상으로 확정되지 않습니다.

각 코드 객체는 독립 프로그램으로 실행되므로 이 모드에서는 다른 코드 객체의 변수·함수·메모리를 상속하지 않습니다.
객체 사이 데이터 전달은 기존 결과 → 코드 연결의 표준 입력으로 가능합니다.
변수와 함수를 유지하려면 기본 **기존 실행 · 환경 유지** 모드를 사용합니다.

결과물은 캔버스 VM의 `/workspace/.compiled-cache`에 코드와 설정의 SHA-256 키로 저장됩니다.
같은 코드와 옵션은 재사용하며 실행 환경 초기화와 VM 재시작 후에도 파일이 유지됩니다.
캐시는 VM 디스크 용량을 사용하며 캔버스 VM 삭제 시 함께 삭제됩니다.
빌드에도 기존 VM 권한·리소스·출력 제한이 적용되며 빌드 제한 시간은 60초입니다.

## API

`POST /api/canvases/{canvasId}/runtime/build`

```json
{"language":"cpp","code":"int main() { return 0; }","passwordGrant":null}
```

기존 실행 API와 동일하게 현재 캔버스 접근, 실행 권한 및 필요한 비밀번호 승인을 확인합니다.
결과의 `exitCode`, `output`, `timedOut`, `truncated`, `environmentReset` 형식은 실행 응답과 같습니다.
기본 실행 모드에서 빌드 요청을 보내면 실행 없이 건너뛰었다는 메시지를 반환합니다.
클라이언트는 실행 API를 계속 사용하며, 서버에 저장된 언어별 `executionMode`가 실행 경로를 결정합니다.

실행 상태는 중앙 알림 대신 각 코드 블록의 테두리에 표시합니다. 대기·실행되지 않음은 회색 점선, 실행 중은 파란색, 성공은 초록색, 실패는 빨간색입니다. 재실행하면 해당 그래프의 상태를 다시 표시하고, 코드를 변경하면 이전 실행 결과의 테두리는 숨깁니다. 실행 환경 초기화 시 상태도 초기화합니다. 상태는 실행을 요청한 클라이언트의 UI 상태이며, 실행 결과 객체의 내용은 기존 방식으로 공유합니다.
