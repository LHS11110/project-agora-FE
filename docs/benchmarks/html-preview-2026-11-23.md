# HTML 미리보기 빈 화면 수정 전후 프레임 측정 — 2026-11-23

HTML 객체의 미리보기가 간혹 흰 빈칸으로 남던 문제를 고친 뒤([HtmlObject.jsx](../../src/canvas/content/HtmlObject.jsx)), 프레임에 영향이 있는지 수정 전후를 비교했다.

- 원본 데이터: [수정 전 일반 CPU](html-preview-2026-11-23-before-cpu1.json) · [수정 후 일반 CPU](html-preview-2026-11-23-after-cpu1.json) · [수정 전 CPU 4배 감속](html-preview-2026-11-23-before-cpu4.json) · [수정 후 CPU 4배 감속](html-preview-2026-11-23-after-cpu4.json)
- 측정 스크립트: [scripts/benchmark-canvas-frames-browser.mjs](../../scripts/benchmark-canvas-frames-browser.mjs), 시나리오 `html-8`(이번에 추가)과 `empty`

## 원인과 수정

미리보기 iframe은 대기용 페이지(`public/html-preview.html`)를 먼저 띄우고, 부모에 `frelog-preview-ready`를 보낸 뒤 실제 문서를 받는다. 부모 쪽 수신기를 `useEffect`에서 등록했기 때문에, 렌더가 몰리면 등록이 늦어졌다. 그 사이에 도착한 준비 메시지는 버려지고, iframe은 대기용 페이지(흰 배경)에 멈췄다.

수정 내용:
- 수신기를 `useLayoutEffect`에서 등록한다.
- iframe의 `load` 때도 문서를 보낸다. 대기용 페이지는 첫 문서만 받으므로 중복은 무시된다.

## 렌더링된 미리보기 수 (CPU 4배 감속, 운영 빌드)

HTML 객체 8개, 처음 연 뒤 5초 대기 → 이동 → 확대·축소를 3회 반복하고, 단계마다 문서가 실제로 그려진 미리보기 수를 셌다(2회 실행).

| 빌드 | 처음 | 1회차 이동 / 확대·축소 | 2회차 | 3회차 |
| --- | --- | --- | --- | --- |
| 수정 전 | 4/8 | 4/8 · 5~6/8 | 5~6/8 · 6/8 | 6/8 · 7/8 |
| 수정 후 | 8/8 | 8/8 · 8/8 | 8/8 · 8/8 | 8/8 · 8/8 |

수정 전에는 미리보기의 절반가량이 흰 빈칸이었다. 그래서 아래 프레임 표의 수정 전 값은 iframe 문서를 덜 그린 상태에서 나온 값이다.

## 프레임 (중앙값, 3회 반복, 25ms 넘는 프레임을 지연으로 계산)

| CPU | 빌드 | 시나리오 | 정지 | 이동 | 스크롤 | 확대·축소 |
| --- | --- | --- | --- | --- | --- | --- |
| 일반 | 수정 전 | html-8 | 0% | 0% | 0% | 0% |
| 일반 | 수정 후 | html-8 | 0% | 0% | 0% | 0% |
| 4배 감속 | 수정 전 | html-8 | 0% | 0.2% | 0% | 0.3% (반복별 0 / 0.3 / 0.7) |
| 4배 감속 | 수정 후 | html-8 | 0% | 0.3% | 0% | 1.3% (반복별 1.3 / 1.3 / 3.3) |

모든 단계에서 p95는 16.7~16.8ms로 같다.

## 해석

- 일반 CPU에서는 차이가 없다.
- CPU 4배 감속의 확대·축소에서 지연 프레임이 0.3%에서 1.3%로 늘었다. 이 차이는 수정 코드 자체의 비용이 아니다. 수정 코드가 하는 일은 iframe마다 `postMessage` 한두 번이다. 확대·축소 중에는 렌더 창을 벗어난 DOM 객체가 제거됐다가 다시 만들어진다([2026-11-22 측정](canvas-frames-2026-11-22.md)의 원인 3). 수정 후에는 다시 만들어진 iframe이 모두 실제 문서를 불러와 그리고, 수정 전에는 그중 일부가 빈 채로 남아 일을 덜 했다.
- 약 57ms 긴 작업은 수정 전 3회차에도 있었다(58ms). 확대·축소 중 iframe 재생성에서 나오는 기존 비용이다.
- 수정 후 값(1.3%)은 2026-11-22 측정에서 다른 객체 종류의 확대·축소 지연 범위(0.7~3.5%) 안에 있다.

## 측정 조건

Chrome 158.0.8127.36 헤드리스, 1800×1100, NVIDIA GeForce RTX 3060 Ti (ANGLE / OpenGL ES 3.2), Intel Core i5-12400F. 커밋 `ae63239` + 커밋하지 않은 수정. `vite build --sourcemap`으로 수정 전후를 각각 빌드한 뒤 `vite preview`로 띄웠다. API와 실시간 브로커는 모의 응답으로 대체했다.
