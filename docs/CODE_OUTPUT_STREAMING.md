# 실행 결과의 실시간 출력

VM runner가 stdout/stderr를 읽을 때 UTF-8 경계를 보존한 출력 조각을 전달한다. 이 조각은 VSOCK → Unix manager → Spring NDJSON → HTTPS 브라우저 경로로 전달된다. 기존 단일 JSON 실행 API도 유지한다.

`POST /api/canvases/{id}/runtime/execute/stream`은 기존 실행 요청과 동일한 인증·접근·실행 권한 및 비밀번호 인증을 확인한다. 출력은 `{"type":"output","output":"..."}`으로, 종료 결과는 `{"type":"result","result":{...}}`로 전달한다. 프록시 버퍼링과 해당 경로의 압축을 끄고 프레임마다 응답을 flush한다. 실행 제한 15초, 출력 제한 64KiB, 입력/코드 제한 64KiB는 유지한다.

브라우저는 첫 출력부터 연결된 결과 객체를 갱신한다. 같은 코드의 조각을 별도 결과로 쌓지 않고 하나의 항목을 갱신하며, 마지막에 종료 코드를 표시한다. 결과 객체를 여러 개 연결하거나 결과 객체끼리 연결한 경우에도 모두 갱신한다. 캔버스 변경은 최대 약 100ms 간격으로 묶어 기존 브로커의 저장 후 브로드캐스트 경로를 거친다. 다른 사용자와 새로 접속한 사용자도 저장된 결과를 받는다.

다음 코드의 표준 입력은 앞 코드가 끝난 뒤 확정된 전체 출력으로 구성한다. 출력 스트리밍이 실행 순서·위상 정렬이나 표준 입력 전달 방식을 바꾸지는 않는다. 연결되지 않은 결과 객체에는 출력하지 않는다. 전송 실패 시 코드를 자동 재실행하지 않으며 이미 발생한 출력은 오류와 함께 보존한다.

언어·라이브러리 자체의 출력 버퍼에 남은 내용은 flush된 시점에 전달된다. 예를 들어 Python `print(..., flush=True)`, C++ `std::endl`/`std::flush`, C `fflush(stdout)`를 사용할 수 있다. 일반 Python 워커는 `-u`로 실행된다.

## 검증

- 실제 KVM의 Python/C/C++/JavaScript/Java/Bash에서 종료 전 여러 출력 프레임 수신, Unicode 및 최종 출력 일치, 기존 비스트리밍 API와 실행 환경 유지 확인.
- 프런트엔드: UTF-8/JSON 경계 분할, 조기 연결 종료, 실행 중 다중 결과 객체 갱신·빈도 제한·최종 항목 교체 검사.
- 서버: 실제 Unix 소켓에서 종료 전 출력 수신, 스트림 순서와 실행 권한 검사, 비인증 요청 거부 검사.
- 브라우저 통합 테스트: `tests/integration/runtime-output-stream.mjs`. 독립 테스트 캔버스·계정 fixture를 사용한다.

배포 후 실제 HTTPS 측정에서 첫 출력은 약 0.44초, 다음 출력과 종료 결과는 약 2.44초에 수신됐다(예제의 대기 2초 포함). 두 사용자 브라우저와 두 연결 결과 객체는 실행 종료 전에 첫 출력을 표시했고, 최종 결과가 같은 항목에 저장되며 재접속 후에도 복원되는 것을 확인했다. 이는 해당 테스트 환경의 측정값이다.

검사 결과: FE Node 317개 통과, Spring 246개 중 243개 통과·환경 조건 3개 건너뜀, 런타임 Python 42개 통과.

브라우저 통합 fixture는 `{canvasId,users:[{token,user},{token,user}]}` 형식의 비공개 JSON 파일을 `AGORA_E2E_STATE`로 전달한다. 해당 캔버스에는 `exec → code → out → mirror` 연결이 필요하고, code는 `FIRST_STAGE`, 2초 대기, `SECOND_STAGE`, 2초 대기, `DONE`을 순서대로 출력하도록 구성한다. 두 계정 모두 해당 캔버스에 초대돼 있어야 한다. 실제 토큰을 저장소에 기록하지 않는다.
