# 12,000개 객체의 60 FPS 검증

2026-10-14, NVIDIA RTX 3060 Ti 8GB(드라이버 595.99.02), Chrome 155, 1800×1100 화면과 DPR 1에서 확인했습니다. 실제 어댑터는 `ANGLE (NVIDIA Corporation, NVIDIA GeForce RTX 3060 Ti/PCIe/SSE2, OpenGL ES 3.2)`입니다. 어댑터 이름을 바꾸는 테스트용 우회는 사용하지 않았습니다.

headless Chrome의 기본 설정은 소프트웨어 렌더링을 선택할 수 있습니다. 이번에는 `--enable-gpu --use-gl=angle --use-angle=gl-egl --ignore-gpu-blocklist`로 실제 GPU를 연결했습니다. 이전 보고서의 소프트웨어 측정은 서버에 GPU가 없다는 의미가 아니며, 그 설명을 수정했습니다. [Chromium의 headless GPU 안내](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/docs/gpu/using-gpu-hardware-in-headless-chrome.md)를 참고했습니다.

| 총 객체 12,000개 | 평균 FPS | 이동 프레임 95백분위 | 객체용 HTML |
| --- | ---: | ---: | ---: |
| 반복 도형 | 60.00 | 17.1ms | 0 |
| 넓게 분산된 도형 | 59.99 | 17.0ms | 0 |
| 색이 모두 다른 도형 | 59.99 | 17.2ms | 0 |
| 도형·일반 텍스트 혼합 | 60.00 | 17.0ms | 0 |
| 전체 선택 | 59.98 | 18.7ms | 0 |
| 연속 확대·축소 | 60.00 | 17.0ms | 0 |

실제 CanvasPage에 12,000개 객체를 주입하고 전용 임시 캔버스의 브로커 쓰기를 차단했습니다. 모델과 모든 래스터 준비가 끝난 뒤, 프레임마다 이동 또는 확대·축소 입력을 전달해 180개 프레임을 측정했습니다. 평균 FPS는 프레임 간격의 평균으로 계산하며 중앙값만으로 60 FPS를 판정하지 않습니다. 분산된 장면은 화면 및 준비 영역과 겹치는 객체만 렌더링합니다. [원시 결과](canvas-60fps-benchmark.json)에 어댑터·캐시·실제 렌더링 객체 수·최대 프레임 시간을 보존했습니다.

초기 네트워크 다운로드·백엔드 처리량은 측정에 포함하지 않습니다. 최초 캐시 준비는 이 실행에서 로컬·배포 검증에서 약 0.24~5.29초가 걸렸고, 일부 프레임은 16.7ms를 넘었습니다. 이 결과는 위 GPU와 장면에서 평균 60 FPS를 확인한 것이며 모든 장치·모든 콘텐츠·최초 로딩의 무지연 보장이 아닙니다. 소프트웨어 경로는 추가 개선 과정에서 별도로 측정했고 같은 화면에서 약 53~57 FPS였습니다. 이 중간 결과는 최종 GPU 검증과 구분해 원시 파일에 보존했습니다.

카메라 입력을 프레임마다 합치고 React의 객체 목록·설정 패널 갱신 빈도를 줄였습니다. 벡터 표면은 화면 좌표로 렌더링하며 HTML 편집기와 선택 조작 요소만 세계 좌표를 사용합니다. PixiJS 렌더 그룹은 카메라 변환을 처리하고, 이미 안티앨리어싱된 래스터 텍스처를 사용해 중복 MSAA 비용을 줄입니다. 색이 다른 불투명 사각형도 흰색 텍스처 하나와 tint를 공유하지만 투명 채우기·테두리·그림자·선택 윤곽·그림체는 원래 렌더링을 유지합니다. [PixiJS 렌더 그룹 안내](https://pixijs.com/8.x/guides/components/scene-objects/container)를 참고했습니다.

확대·축소 중에는 기존 텍스처와 미니맵 비트맵을 투영하고 멈춘 뒤 품질을 갱신합니다. 품질 갱신 때 스프라이트를 파괴·생성하지 않고 재사용합니다. 소프트웨어 경로는 투명 영역을 줄이고 OffscreenCanvas Worker가 내용 변경 때 캐시를 준비하며, 카메라 이동은 합성 변환만 수행합니다. Worker가 실패하거나 지원되지 않으면 메인 스레드의 Canvas 2D로 복원합니다. [OffscreenCanvas 전송 API](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/transferControlToOffscreen)를 사용했습니다.

Node 테스트 89개와 실제 브라우저의 텍스트·코드·메모 저장 및 재접속, 깊이 선택, 이동·모서리 크기 조절, 드로잉·그림체 화살표 선택 검증을 통과했습니다. GPU 컨텍스트를 잃은 경우 Worker로 복원되는 것을 확인했고, 원래 채우기 색상은 GPU와 Worker 화면의 픽셀 값 모두 일치했습니다. 부분 갱신 결과도 강제로 전체를 다시 그린 결과와 일치했습니다.

Project Orchestra로 최종 배포한 실제 서비스에서도 네 가지 장면의 이동과 연속 확대·축소 평균 59.99~60.00 FPS를 확인했습니다. 배포 후 혼합 장면의 최초 캐시 준비는 약 5.29초였으며, 준비 이후 프레임 95백분위는 17.0ms였습니다.

배포한 서비스의 12,000개 전체 선택 상태에서도 평균 59.99 FPS와 95백분위 18.6ms를 확인했습니다.
